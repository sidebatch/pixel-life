# 낚시·벌목 성장 균형 v2

2026-10-12 사용자 승인으로 적용한 현재 기준이다. 시뮬레이션 후보였던 수치를 실제 게임 데이터·저장 이행에 연결했다. 농사 성장이나 다른 콘텐츠 구현을 승인한 문서가 아니다.

`src/data/life-content-data.js`의 50종 `xp`는 실제 지급량이다. 과거 기준값 × 5% 계산은 폐기했다. 타격 중에는 지급하지 않고 완전 벌목 때 한 번 지급한다. 목재 0/1/2/3개 균등 드롭, 0개일 때도 XP/발견 기록 지급, 기존 도끼 제한·가격·수리·재료·나무 HP는 그대로다.

낚시의 어종별 XP, 10종 발견 +240 XP, 추첨·시간·날씨·장비·항로는 변경하지 않았다.

## 공통 레벨업 요구량

`src/data/life-skill-data.js`의 `LIFE_SKILL_XP_CURVE_VERSION=2`가 현재 버전이다. 원래 요구량은 `LIFE_SKILL_LEGACY_XP_TABLE`에 보존한다.

- Lv.1에서 Lv.80 도달까지의 요구량은 원래와 같다.
- 현재 레벨이 80~99이면 원래 다음 레벨 요구량 × `1 + 3 × (현재 레벨 - 79) / 20`을 반올림한다.
- Lv.80→81: 2,139 XP, Lv.90→91: 6,387 XP, Lv.99→100: 11,620 XP.
- Lv.100 누적 요구량: 106,690 → **187,230 XP**.
- 낚시·벌목은 같은 곡선을 쓰며 서로의 XP는 올리지 않는다.
- Lv.100 이후 숙련도 요구량 4,000 + 숙련도 × 250은 유지한다.

보상을 높이면서 최종 장비보다 Lv.100이 먼저 되는 성장 역전을 막기 위해 후반을 늘린 안이다. 숫자만 확대하는 변경이 아니며, 실제 후반 레벨업 시간이 길어진다.

## 기존 저장 이행

저장 키 `pixel-life.save.v2`와 저장 버전 2는 유지한다. 낚시·벌목 진행에 `xpCurveVersion:2`를 각각 저장한다. 버전이 없거나 1인 진행은 원래 곡선으로 먼저 해석한다.

- 기존 레벨과 경험치 바 비율을 보존한다. 새 요구량에서 정수 XP로 올림 환산해 표시 진행률이 뒤로 가지 않게 하며, 환산만으로 레벨업하지 않는다.
- 이미 Lv.100인 진행은 레벨·숙련도·숙련도 안의 XP를 그대로 보존한다.
- 과거 Lv.20 상한 이후에도 쌓인 누적 XP는 원래 곡선으로 먼저 복구한 뒤 이행한다.
- 재접속·저장·재접속을 반복해도 다시 환산하지 않는다. 한 스킬만 이행된 혼합 저장도 개별 처리한다.
- 코인·밭·작물·아이템·도감·장착/소유 장비·내구도·운항은 기존 저장 규칙을 그대로 사용한다.
- 총 XP 숫자는 새 곡선에 맞게 환산된다. 기존 총 XP 숫자와 레벨/진행률을 모두 유지하는 변경은 아니다.

`src/save.js`의 `normalizeSavedLifeSkillProgress`가 두 스킬의 이행을 담당한다. 새 게임은 처음부터 현재 버전으로 시작한다. 불러올 때 사용자 저장을 삭제하거나 새 네임스페이스를 만들지 않는다.

## 시뮬레이션 근거

낚시 40개 장비 성장 경로, 목재 0~3개를 실제로 추첨하는 벌목 384개 경로를 비교했다. 보통 입력에서 비교 시점의 누적 XP 상대 차이는 평균 6.45%, 보정에 쓰지 않은 표본은 6.92%였다. 순간적인 10분 성장량이나 모든 플레이가 항상 이 범위에 든다는 의미는 아니다.

| 같은 플레이 시간 | 낚시 진행도 | 벌목 후보 진행도 |
| --- | ---: | ---: |
| 30분 | 15.2 | 14.2 |
| 1시간 | 21.5 | 21.1 |
| 3시간 | 37.7 | 38.8 |
| 10시간 | 72.2 | 72.7 |
| 12시간 | 80.1 | 80.0 |

소수점은 레벨 내부 진행률이다(21.5 = Lv.21에서 약 50%). 최고 장비 이후 낚시는 빙하 운항/파손 후 기본 도구 대체/항구 부분 수리, 벌목은 10단계 나무/태초 도끼/마을 수리로 이어서 계산했다.

| 입력 가정 | 낚시 Lv.100 중앙 시간 | 벌목 Lv.100 중앙 시간 |
| --- | ---: | ---: |
| 매우 빠름 | 19.1시간 | 22.7시간 |
| 보통 | 30.0시간 | 30.2시간 |
| 느림 | 48.1시간 | 49.8시간 |

전체 경로와 매번 목재 1개인 별도 3조건에서 최종 장비를 먼저 얻었다. 모든 가능한 난수 결과에 대한 보장은 아니다. 입력·나무 이동·수리 왕복은 가정이며 Android 실측이 아니다. 재생 대기와 실제 길찾기/마을 거리는 제외했다. 매우 빠른 입력의 차이는 남아 있다.

로컬 세부 자료는 `output/xp-growth-study/report.md`와 JSON에 보존했다. 이 자료는 적용 전 코드 지문과 후보 계산의 역사이며, 데이터 변경 후 같은 원본 검토 스크립트를 다시 실행하면 지문 불일치를 감지하도록 되어 있다. 현재 게임 값은 소스와 아래 검사가 기준이다.

기존 `simulate-forestry-balance.mjs`도 새 지급량/곡선을 읽는다. 그 단순 평균 모델은 수리 왕복을 제외하며 실제 보정용 무작위 모델과 다르다. 현재 평균 1.5개 모델은 7,262그루/94,469 XP/Lv.89, 고정 1개 모델은 11,626그루/151,310 XP/Lv.96이다. 옛 59,210 XP/Lv.80 표는 역사다.

## 검증

```text
node scripts/qa-life-skill-growth.mjs
node scripts/check.mjs
node scripts/build.mjs
node scripts/qa-life-skill-growth-browser.mjs
```

단위 검사는 1,356개 기존/현재 저장 이행, 모든 레벨 경계, Lv.100 숙련도, 50종 지급량, 실제 저장/복원에서 코인·도구·아이템 보존을 검사한다. 기본 검사에 포함했다. 브라우저 검사는 별도 Playwright/Chrome 및 dist 서버를 사용하며 393/320px의 실제 +7 지급·저장·높은 레벨의 바·숙련도·재접속을 확인한다. 사용자 브라우저 저장은 사용하지 않는다.

숲 V1 지문은 보존한다. 승인된 XP 변경은 `FOREST_ROUTES_BASELINE_V2.json`에만 반영했고, 생성 시 12숲의 나무/물/지형 지문 및 모든 비-XP 나무/도끼 데이터가 기존과 동일함을 확인했다.
