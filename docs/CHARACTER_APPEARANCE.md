# 캐릭터·옷·도구 공통 규격 v1

## 적용 범위 (2026-09-25)

사용자가 요청한 1~4단계(기본 규격 → 외형 분리 → 기본 동작 → 현재 장비 연결)를 적용했다.
기존 캐릭터의 얼굴·머리·기본 옷·가방을 유지하고, 동작별 그림을 같은 셀/발 기준으로 정규화했다.
이번 작업은 캐릭터 생성 UI·옷 상점·새 의상 판매를 추가하는 작업이 아니다.

## 1. 공통 좌표

- 모든 게임용 캐릭터 레이어는 **96×96 셀**, 발 기준 **(48,88)** 를 사용한다.
- 게임에서 셀을 100×100으로 표시한다. 그림 자체의 높이는 약 68px(표시 시 약 71px)이며 동작마다 몸 크기를 바꾸지 않는다.
- 걷기·대기는 3×4칸 **288×384**, 벌목은 2×4칸 **192×384**, 낚시는 3×4칸 **288×384**다.
- 방향 행은 아래/오른쪽/왼쪽/위 순이다. 왼쪽 몸 그림은 오른쪽 레이어를 반전하지만, 장비 손은 오른손이라는 기준을 별도로 유지한다.
- PC/모바일 이동·충돌·속도는 변경하지 않았다. 모바일 actor 위치 스냅도 유지한다.

| 동작 | 가로 프레임 | 손·장비 |
| --- | --- | --- |
| 대기/걷기 | 0: 대기, 이동: 0→1→2→1 | 각 프레임의 실제 손 위치를 따라 이동 |
| 벌목 / 허공 휘두름 | 준비 / 타격 | 270ms 자세 전환. 나무가 있을 때만 피해·타격음·보상 발생 |
| 낚시 | 투척 준비 / 대기 / 당기기 | 투척 첫 구간→대기, 획득 시 당기기. 입질은 대기 자세 유지 |

각 프레임의 손 좌표·도구 목표 각도·전후 표시를 `src/data/character-rig-data.js`에 저장한다.
캐릭터 몸 옆에 고정 오프셋을 적용하거나 도구 전체 사각형의 모서리를 손 위치로 사용하는 방식은 사용하지 않는다.

벌목/허공 휘두름의 Head/Hair는 해당 방향 walk 0번을 같은 배율로 사용하되 목 (48,63) 기준 chop의 headMotion(이동·회전)을 함께 적용한다. 위치까지 고정하면 몸과 분리돼 보이므로 준비/타격에 맞춰 1~2px 이동·최대 0.05rad 기울며 좌우는 대칭이다. 원본 머리 폭 차이에 따른 확대 없이 움직임을 유지한다. 몸·옷·배낭·그립은 chop 프레임으로 계속 움직인다. 새 body/hair ID도 같은 경로를 따르고 머리 배율은 유지해야 한다. 패킹된 chop head/hair는 원본 검증·재합성용으로 보존한다.

## 2. 실제 레이어

2026-09-26 측면 벌목 가방 수정: 오른쪽 타격 가방의 윗부분/테두리(y54~60)를 `backpackTopRows` 행별 마스크로 분리하고 왼쪽은 반전한다. 기존 색상/y 분류는 이 영역을 Hair/Head에 섞어 넣어, 실제 walk 머리 교체 렌더링에서 가방이 잘려 보였다. 원본 픽셀은 그대로 옮기며 기본 재합성은 동일하다. 가방 윗부분은 머리 레이어 교체 시에도 남고 가방 ID/색상 변경을 따른다. 모션·머리 크기·목 움직임·도구 그립·타격 시점은 바꾸지 않았다. 새로운 외형 원화에도 부품 경계를 색상만으로 판단하지 말 것.

게임용 PNG는 `assets/player/rig-v1/`에 있다. 걷기·벌목·낚시 각각 다음 여섯 레이어를 제공한다.

- body: 옷 아래 torso/팔/다리가 있는 기본 몸. 중립적인 베이지 기본 이너를 포함한다.
- head: 머리카락 아래 둥근 머리와 얼굴.
- hair: 현재 갈색 머리카락.
- outfit: 여행자의 옷·바지·신발.
- backpack: 현재 배낭.
- grip: 도구 위에 표시할 손과 손 외곽.

기존 그림에서 옷만 지워 빈 몸을 만드는 방식이 아니다. 생성한 몸 원화를 같은 자세로 맞춘 뒤 기본 의상 아래 영역을 채웠다.
기본 외형의 모든 레이어를 합친 결과가 정규화된 기준 그림과 픽셀 단위로 동일한지 자동 검사한다.
머리·옷·가방은 별도 PNG이므로 교체 이미지에 포함시키지 않는다.
기본 외형 contour 안에서 제작한 몸이므로 향후 체형 자체를 바꾸려면 해당 체형의 body/head/grip과 옷 대응 시트를 새로 제공해야 한다.

저장 ID는 `body.starter`, `hair.brown`, `outfit.traveler`, `pack.traveler`다.
이전 저장에 새 ID가 없거나 알려지지 않은 ID가 있으면 기본값으로 보정한다. 기존 돈·레벨·구매 장비·가방은 유지한다.
외형 목록은 `src/config.js`의 `CHARACTER_PARTS` / `CHARACTER_OUTFITS`에서 등록한다.

## 3. 도끼·낚싯대 규격

- 현재 도끼 4종·낚싯대 6종을 모두 **96×96 게임용 도구 PNG**로 정규화했다.
- 각각 실제 손잡이의 grip 좌표와 tip 좌표, 원래 축 각도/길이를 갖는다.
- 그립을 캐릭터의 프레임별 손 좌표에 연결한 뒤 회전·배율·좌우 반전을 적용한다.
- 정면/오른쪽 측면: 몸·옷·가방 → 도구 → 머리·머리카락 → 손 순으로 표시한다.
- 뒤쪽/왼쪽 측면: 도구 → 몸·옷·가방 → 머리·머리카락 → 손 순이다. 몸 뒤의 오른손·도구 일부가 가려질 수 있다.
- 주 손은 캐릭터의 오른손이다. 정면 대기에서는 화면 왼쪽 손, 뒤에서는 화면 오른쪽 손에 연결한다. 왼쪽 측면의 대기·이동은 반전된 앞팔이 아닌 뒤쪽 팔 좌표를 사용한다. 두 손을 모으는 벌목·낚시는 공통 손잡이 지점을 사용한다.
- 앞·뒤 대기/걷기의 도끼는 날이 앞을 향하되 옆면도 조금 드러나는 시점이다. 오른손 그립과 손잡이 길이를 유지한 채 축 각도를 각각 -1.95/-1.19rad로 두고 축에 수직인 너비만 55%로 투영한다. 이전 30%는 너무 얇다는 사용자 피드백으로 조정했다. 좌우 모습·휘두름·낚싯대에는 이 보정을 적용하지 않는다. 원본 PNG/셀 규격은 변경하지 않는다.
- 낚싯줄은 표시 중인 낚싯대의 tip에서 찌로 이어진다. 도구 아이콘에 그려진 늘어진 줄은 전처리에서 잘라내고 동적 줄을 사용한다.
- 상점·가방 아이콘용 기존 고해상도 파일은 원본 그대로 유지한다. 이동 중 표시를 위해 그 큰 파일을 추가로 디코딩하지 않는다.
- 손의 장비 슬롯은 하나다. `appearance.activeTool`이 실제 장착 종류이며 가방에서도 그 종류의 선택 장비 하나만 `장착 중`으로 표시한다. 옷은 별도 외형 슬롯이다. 도끼 ID와 낚싯대 ID는 각 종류에서 마지막으로 선택한 제품을 기억하며, 비활성 종류는 장착 상태가 아니다.
- 도끼를 들면 물가에서도 도끼를 휘두르고 낚시는 시작하지 않는다. 낚싯대를 들고 물을 바라볼 때만 낚시하며, 나무 앞에서도 도끼로 자동 전환하지 않는다. 낚시/휘두름 중 장비 변경은 막는다. 실제 행동 진입 함수와 대상 판정 양쪽에서 검사한다. 기존 소유 장비·진행도·저장 형식은 유지한다.
- 도끼를 들고 빈 땅에서 Space/Z 또는 모바일 행동 버튼으로 허공 휘두르기를 한다. 대상 있는 상호작용이 우선이고 허공에서는 진행도를 변경하지 않는다. 재입력은 진행 중인 동작을 초기화하지 않는다.

새 무기도 이 좌표 계약을 따라야 한다. 서로 다른 손 위치/체형을 가진 그림을 단순히 같은 해상도로 저장하는 것으로는 충분하지 않다.
동작이 다른 무기군을 추가하면 대응 pose, 손 좌표, 모든 외형의 대응 시트도 함께 추가한다.

## 4. 제작·재현

`scripts/pack-character-rig.mjs`가 제작 원본을 정규화하고 레이어/도구 PNG·manifest·동작 데이터를 만든다.
PNG 처리는 Node 내장 기능만 사용하는 `scripts/lib/png.mjs`에서 수행한다. 외부 이미지 패키지 설치는 필요 없다.

```bash
node scripts/pack-character-rig.mjs
node scripts/check.mjs
node scripts/build.mjs
```

제작 원본·생성 프롬프트·내장 이미지 제작 도구 사용 기록은 `assets/player/source/rig-v1/README.md`를 참고한다.
기존 원본은 덮어쓰지 않았다. 생성본에 인접 프레임의 일부가 겹치는 경우 큰 연결 영역을 선택해 잘못된 축소/늘어남을 막는다.

새 의상은 walk/chop/fish **세 시트를 모두** 갖춰야 한다. 누락·크기가 잘못된 경우 로딩 단계에서 실패시켜 잘못된 옷이 동작마다 섞이지 않게 한다.
외형 교체 조합 테스트(5번)는 색상 변형 세트로 적용했다. 다른 형태의 머리/옷/가방 제작과 조합 검증은 별도로 남아 있다.

## 시험용 외형 비교

`https://sidebatch.github.io/pixel-life/?appearance-preview` 에서만 녹색 옷·금발·붉은 가방을 표시하고 기본/옷/머리/가방/전체 버튼으로 비교한다.
등록 ID는 `outfit.trial.green`, `hair.trial.blond`, `pack.trial.red`이다.
기존 walk/chop/fish 분리 PNG에서 Canvas 색상 변형 9레이어를 만들고, 알파와 셀·손/발 위치는 그대로 유지한다. 원본 PNG는 수정하지 않는다.
이 세트는 새 모양을 만든 판매용 그림이 아니라 교체 경로를 검증하는 프로토타입이다.
표시용 오버라이드는 실제 외형·구매 목록을 변경하지 않으며 저장되지 않는다. 게임 행동에 따른 기존 진행도 저장은 정상 동작한다.
일반 링크는 추가 레이어를 만들거나 시험 ID를 등록하지 않는다. 저장 복원은 시험 ID를 안전한 기본 외형으로 보정한다.

`scripts/qa-appearance.mjs`는 9레이어의 알파 일치와 색상 차이, 8개 조합의 256자세, 장비 위치 유지, 모바일 비교 버튼과 저장/일반 링크 복귀를 검사한다.
`PIXEL_LIFE_QA_APPEARANCE=trial`로 `scripts/qa-character.mjs`를 실행하면 같은 세트로 실제 낚시·벌목·허공 동작을 검사한다.

## 5. 검증과 남은 항목

- 자동: 32개 방향/동작 프레임, 18개 레이어의 크기·재합성, 의상 아래 몸 존재, 10개 도구의 그립, 총 320개 프레임×도구 연결, 좌우 반전, 앞뒤 가림, 기존 저장/낚시/벌목 규칙 검사.
- 로컬 Chrome: 같은 게임 렌더러의 32프레임 검토 화면과 10개 도구 표시, 393×780 모바일 모의 네 방향 대기/낚시/벌목.
- 실제 게임 함수: 낚시 시작→대기→입질→획득·XP, 벌목 준비→타격(HP 100→80), 네 방향 허공 휘두름(Space/Z/터치)과 보상·저장 변화 없음.
- 단일 장착 회귀: `scripts/qa-held-tool.mjs`로 가방 카드·손 선택, 장착 표시 하나, 물가 도끼 Space/Z/터치, 낚싯대 실제 획득/XP, 낚싯대의 벌목 차단, 행동 중 교체 차단, 장착/진행도 재접속 복원을 검사한다.
- 추가 검증: 시험 세트 9레이어 알파/크기 일치, 8개 부품 조합×32자세, 저장 오염 방지, 실제 낚시·벌목·허공 동작.
- 아직 안 한 것: Android 실기기 손 조작/성능, 다른 모양의 새 외형 조합, 캐릭터 생성·의상 상점.

브라우저 검토는 선택적으로 `scripts/qa-character.mjs`를 실행한다. 별도 Playwright와 Chrome을 사용할 수 있으며 경로는 `PIXEL_LIFE_PLAYWRIGHT` / `PIXEL_LIFE_CHROME` 환경 변수로 지정한다.
생성 스크린샷은 배포에 포함하지 않는다.
