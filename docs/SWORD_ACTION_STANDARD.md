# 검 동작 규격 v1

공통 캐릭터 기준은 `CHARACTER_ASSET_STANDARD.md`와 `character-standard-v4.json`, 검 동작의 기계 판정값은 `sword-action-v1.json`이다. 기존 몸·옷·가방·96×96 셀·100×100 표시·발 `(48,88)`·오른손 grip·도끼/낚싯대는 그대로 둔다. 이전 v3 계약은 기본 검 제작 당시의 기록으로 보존한다.

- 검은 도끼와 별개인 `sword` 동작군이다. 현재는 검 손/몸 2프레임에 기존 `chop` 레이어를 재사용하되, 검의 방향별 각도·길이·가림을 `src/data/sword-data.js`에서 독립 지정한다. 새 검 때문에 도끼 각도나 캐릭터 배율을 조정하지 않는다.
- 4방향 행은 아래·오른쪽·왼쪽·위다. 휘두름은 준비 270ms, 종료 700ms이며 걷기 중에는 한 손에 든 검을 보인다. 외형/머리/가방은 두 성별의 현행 레이어와 동일하게 합성한다.
- 앞방향 타격은 화면 아래쪽으로 끝난다. 뒷방향은 오른손 쪽의 검날이 화면 오른쪽에서 왼쪽으로 이동한다. 검은 머리 뒤 레이어에서 렌더링해 중앙 부분만 머리에 가리고, 양옆의 가려지지 않은 검날은 보여야 한다. 뒤쪽 두 프레임과 남녀 헤어를 실제 캐릭터 합성에서 확인한다.
- 검 이미지는 투명 96×96 PNG 하나이며 캐릭터·손·효과를 포함하지 않는다. 실제 손잡이 `grip`, 칼끝 `tip`, 두 점에서 계산한 `nativeAngle`·`nativeLength`를 `SWORD_TOOLS`에 등록한다. 기본 검의 기준은 `(25,69)→(81,15)`, 휴대 `carryLength:30`, 휘두름 `swingLength:38` 원본 픽셀이다.
- 더 긴 검은 **자기 원화와 metadata의 `carryLength`·`swingLength`만** 길게 한다. 예를 들어 차기 검에 36/48을 지정할 수 있지만 실제 수치는 화면 검토 후 결정한다. 두 길이는 실제 `grip→tip` 축에 적용되는 게임 내 표시 길이이며, 원화 픽셀 길이(`nativeLength`)와 구별한다. 현재 등록 검사는 각 길이 24~64, `swingLength ≥ carryLength`를 요구한다. 이 범위를 넘는 대검은 먼저 새 규격과 화면 검증이 필요하다. 길이가 길어져도 96×96 원화 규격, 손 피벗, 4방향 각도, 2프레임 박자, 머리 뒤 가림, 캐릭터 크기는 그대로다. 새 검을 기존 30/38에 강제 축소하지 않는다.
- 등록 순서: 새 검 PNG → `SWORD_TOOLS`에 실제 grip/tip·축각·축길이·두 표시 길이 → `SWORD_TOOL_URLS` 경로 → `SWORDS` ID/등급/설명. 상위 검의 획득 조건·상점/재료·전투 효과는 별도 설계 후 구현한다. 가방 장착과 저장은 `ownedSwordIds`·`swordId`를 사용하므로 도끼/낚싯대와 동시에 들지 않는다.
- 긴 검의 뒤쪽 휘두름도 오른쪽 검날 → 머리 뒤로 가린 중앙 → 왼쪽으로 나온 검날 순서여야 한다. 길이가 늘어난 만큼 머리 양옆으로 보이는 면적은 달라질 수 있으나, 손잡이나 머리 레이어를 옮겨 맞추지 않는다. 남녀 기본 헤어와 실제 장착 가능한 추가 헤어·옷·가방을 함께 확인한다. 머리 가림을 벗어나는 판타지 대검은 이 규격에 억지로 넣지 말고 새 동작/규격을 제안한다.
- 현재 검은 동작 검증 단계다. 허공·나무 앞에서 휘둘러도 나무/적 피해, 벌목 보상은 발생하지 않는다. 전투가 생길 때 타격 판정·피해·적 반응·효과음은 독립 시스템으로 추가한다.
- 신규 검 납품 시 `node scripts/check-sword-standard.mjs`, `node scripts/check.mjs`, `node scripts/qa-sword.mjs`, `node scripts/qa-character.mjs`를 실행하고 실제 폰 화면에서 남녀 4방향 휴대/휘두름 및 옷·머리·가방 조합을 확인한다. 자동 검사가 미술 품질을 보장하지는 않는다.

기본 검 원본과 가공 기록은 `assets/player/source/sword-v1/PRODUCTION.md`에 있다.
