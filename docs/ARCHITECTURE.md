# Pixel Life Architecture

## 목표

이 프로젝트는 코어 시스템을 안정적으로 유지하면서 생활 콘텐츠를 독립적인 Activity Module로 추가하는 것을 목표로 한다.

생활 스킬 성장의 확정 설계 기준은 [`LIFE_SKILL_PROGRESSION.md`](LIFE_SKILL_PROGRESSION.md)이다. 현재 낚시에는 Lv.1–100·이후 숙련도와 공통 스킬 데이터·UI가 첫 적용되었다. 벌목·농사의 기본 행동·보상·저장은 연결했으나 스킬 XP·레벨 UI는 후속 작업이다. Lv.21 이후 요구량은 임시 밸런스다.

```text
입력 → 시뮬레이션 → 월드 상태 → 렌더링
              └────→ 상호작용/UI
```

## 파일 책임

### `src/assets.js`

개발용 이미지 경로만 관리한다. 월드·캐릭터·건물과 `FISH_URLS`의 25종 물고기, `FOREST_TREE_URLS`·`FOREST_STUMP_URLS`의 숲 나무/그루터기, `LIFE_ITEM_URLS`의 통나무/씨앗 경로를 한곳에서 선언한다. base64 데이터는 소스에 직접 넣지 않으며 빌드 단계에서만 단일 HTML에 포함한다. 생활 콘텐츠 이미지 규격은 `LIFE_ASSET_STANDARD.md`를 따른다.

### `src/config.js`

Canvas, 프로젝트 메타데이터, 지역 및 Activity Module 목록, 공용 게임 상태와 에셋 로딩을 담당한다. 필수 월드 에셋과 캐릭터 규격 PNG는 병렬로 로드한다. 의상은 걷기/벌목/낚시 대응 시트가 모두 있어야 하며 누락·크기 오류는 로딩 실패로 알린다. 고해상도 도구 아이콘을 월드 표시용으로 추가 디코딩하지 않는다.

### `src/data/world-map.js`

마을의 맵 크기, 플레이어 시작점, 지형 구간, 건물, NPC, 고정 오브젝트와 장식을 선언한다. 새 월드 콘텐츠는 렌더링 코드가 아니라 이 파일 또는 같은 규격의 지역 데이터 파일에 추가한다.

### `src/data/region-maps.js` / `src/data/life-content-data.js`

숲·농장의 별도 64×48 맵, 마을과의 양방향 출입구 및 벌목 나무·고정 밭 위치를 선언한다. 벌목 타격/재생 시간, 단계별 밭 확장 비용, 작물 성장·수확·판매 수치는 생활 콘텐츠 데이터로 분리한다. 숲·농장 물가는 낚시 지역과 연결하지만 마을의 전체 어종 임시 미리보기는 유지한다.

### `src/world.js`

선택한 지역 정의를 읽어 타일 Set, 충돌 데이터와 런타임 엔티티를 구성한다. 출입구로 지역을 바꿀 때 이전 타일·NPC·장식 데이터를 제거하고 새 지역을 빌드한다. 시각 표현을 바꾸더라도 이동용 타일 데이터는 가능한 한 유지한다.

### `src/region-music.js`

사용자가 제공한 긴 BGM 세 곡의 지역 매핑·반복·첫 입력 활성화·메뉴 음소거·탭 숨김/복귀를 담당한다. 한 HTMLAudioElement만 사용하고 현재 곡만 metadata preload로 스트리밍한다. 같은 woodland 곡을 쓰는 두 숲의 이동에서는 재시작하지 않는다. 실제 지역 이동은 world.js에서 syncRegionMusic을 호출하고, 저장 복원된 지역도 초기화 시 반영한다. 효과음의 Web Audio 버퍼와 독립되어 낚시 소리를 끊지 않는다. 음소거는 진행도와 별도 키로 저장한다. build.mjs는 BGM MP3 세 개만 외부 스트리밍 파일로 dist에 복사한다.

### `src/world-validation.js`

마을의 건물·NPC 검사에 더해 숲·농장의 좌표, 출입구, 물, 자원 나무와 밭 중복·접근성을 검사한다. 오류가 있으면 게임 시작과 빌드 검사를 실패시킨다.

### `src/debug.js`

F3 또는 URL의 `?debug`로 충돌 타일, 그리드, 건물 footprint, 문, 접근 타일과 NPC 로밍 범위를 표시한다.

### `src/simulation.js`

플레이어 이동, NPC 로밍, 충돌, 카메라 보간과 출입구 진입을 담당한다. 마지막 지역·위치를 복원한다. Activity Module이 이 파일을 직접 크게 수정하지 않도록 한다.

이동 템포는 `src/config.js`의 `MOVEMENT_CONFIG`에서 조절한다. 현재 플레이어 한 타일 이동 시간은 185ms, NPC는 260ms다. 플레이어는 타일 경계에서 속도가 끊기지 않도록 일정 속도 보간을 사용한다. PC 키보드는 다음 한 칸 입력을 버퍼링하고, PC 포인터 환경에서만 캐릭터 위치를 서브픽셀 렌더링한다. 모바일의 기존 픽셀 스냅 경로는 유지한다.

### `src/rendering.js`

지형, 길, 물, 식생, 건물과 캐릭터를 그린다. 숲·농장 출입구, 벌목 상태의 나무/그루터기, 밭의 잠금·성장 단계를 추가한다. 통과 가능한 식생은 actor 아래에 두고, 가림이 필요한 오브젝트는 공용 Y-depth 큐에 넣는다. 시간대 그라데이션·조명·밤 비네팅과 화면 전체 비·폭풍, 낚싯줄·찌·입질 `!`도 이 렌더링 계층에서 처리한다.

플레이어 그리기는 `src/character.js`에 위임한다.

### `src/character.js` / `src/data/character-rig-data.js`

플레이어 그림은 걷기·벌목·낚시·검 모두 96×96 셀/같은 발 기준을 사용한다. body/head/hair/outfit/backpack/grip PNG를 합성하고 각 무기의 실제 손잡이 피벗을 프레임별 손에 연결한다. 위쪽 도구는 몸 뒤에, 그립 손은 도구 위에 그린다. 낚싯줄은 같은 변환으로 구한 낚싯대 끝을 사용한다. 최초 rig 생성은 `scripts/pack-character-rig.mjs`, 현행 승인 기준 PNG의 재현은 `scripts/pack-character-baseline-v2.mjs`가 맡는다. 런타임 색상 마스크 분리는 사용하지 않는다. 외형 저장·등록은 `src/config.js`/`src/save.js`, 도구 선택은 `src/inventory.js`에 있다. 새 제작물의 규격은 `docs/CHARACTER_ASSET_STANDARD.md`와 `docs/character-standard-v4.json`을 따르고 검은 `docs/SWORD_ACTION_STANDARD.md`를 추가로 따른다. `docs/CHARACTER_APPEARANCE.md`는 과거 제작 이력이다.

### `src/interactions.js`

상황별 액션, 대화, 메뉴, 조이스틱, 터치 및 키보드 입력을 담당한다. 공용 근접 대상 선택에서 출입구·NPC·벌목 나무·밭·낚시·건물을 판정하고 각각의 행동으로 전달한다. 낚시가 진행 중일 때는 일반적인 `낚시` 상황 칩으로 되돌아가지 않아 투척·대기·입질 문구를 숨긴다. 모바일 낚시 취소는 `pointerdown`이 아니라 `click`에서 처리해 고스트 클릭을 막는다. 도감·장비·밭 팝업의 브라우저 뒤로가기 상태도 관리한다.

### `src/fishing.js`

낚시의 `idle → casting → waiting → bite → result` 상태 흐름과 지점·시간·날씨 필터, 상대 Weight 선택, 같은 어종 3연속 보정 및 XP·발견 통계 갱신을 담당한다. 캐스팅 순간 `regionId + spotId + habitat + period + weather`를 고정해 진행 중 월드 상태가 바뀌어도 같은 풀을 사용한다. 장착한 낚싯대의 입질 대기 감소, 희귀 이상 Weight 증가와 큰 개체 보정도 최종 선택 단계에서 적용한다. 마을·농장은 연못, 숲은 강, 해안 항구는 해안 풀을 사용한다. 과거 전체 어종을 마을에서 미리 잡게 하던 `temporaryAllFishAtVillagePond`는 해안 개방 뒤 `false`로 고정했다. 발견 수가 5/10/15/19/20에 도달하면 데이터에 선언된 보상을 한 번만 자동 지급한다. `?debug&fish=<fish.id>`는 실제 저장·결과 UI를 거치면서 지정 어종의 입질을 즉시 발생시키는 QA 전용 경로다. 실제 출현 중인 어종·설명·보상은 `src/data/fish-data.js`, 10개 서식지와 74종 목표 명단은 `src/data/fishing-habitat-data.js`, 낚시 지점 판정은 `src/fishing-spots.js`, 낚싯대 원본은 `src/data/fishing-gear-data.js`에 둔다.

### `src/fishing-spots.js`

월드의 사각 물 영역과 잘린 모서리 규칙을 사용해 현재 물 타일의 안정적인 `spotId`와 `fishingHabitat`을 반환한다. 모든 새 물 영역은 고유 ID와 알려진 서식지를 가져야 한다. 이전 맵 호환을 위한 지역 기본 서식지도 관리하지만 실제 캐스팅은 물 영역의 명시값을 우선한다. 월드 검증은 서로 다른 서식지 영역이 겹쳐 한 타일의 결과가 모호해지는 것을 막는다.

낚시 결과창의 위치·스크롤·확인 버튼 배치는 `styles/game.css`의 `#dialog.fishingResult` 전용 규칙에서 관리한다. 일반 대화창의 하단 배치는 변경하지 않는다.

### `src/data/life-skill-data.js` / `src/life-skills.js` / `src/skill-ui.js`

생활 스킬 6종의 공통 메타데이터와 요구 XP, Lv.100 이후 숙련도 계산, 진행도 카드·+XP·레벨업 UI를 담당한다. 레벨업 알림이 뜰 때 공용 음향 재생 함수를 호출한다. 현재 낚시·벌목은 스킬 XP 획득·저장까지 연결됐고, 농사는 행동과 재화·자원 저장 단계다. Lv.1–20 요구량은 유지하고 그 이후 요구량은 플레이 테스트 후 조정한다.

### `src/fishing-effects.js`

투척·입질·획득, 레벨업, 상점 판매 성공과 장착 세 계열에 총 여덟 개의 짧은 MP3를 재생한다. 장착음은 도끼·검의 `equip-weapon.mp3`, 옷·가방의 `equip-clothes.mp3`, 낚싯대의 `equip-rod.mp3`로 나뉜다. 여덟 소리는 로딩 중 Web Audio 버퍼로 미리 디코딩해 즉시 시작하고, 오디오 컨텍스트는 첫 입력에서 활성화한다. 버퍼를 사용할 수 없는 환경에서는 HTML 오디오 재생으로 되돌아간다. 레벨업·상점 음원은 낚시 소리와 별개로 재생하므로 획득음을 끊지 않는다. 장착음은 장비 저장이 성공했을 때만 재생한다. 벌목 타격·쓰러짐·도끼 파손·나무 발견과 희귀·영웅·전설 낚시 결과는 Web Audio 합성음을 사용하며, 파손음은 내구도가 실제로 0이 된 타격에 한 번만 재생한다. 일반·고급 낚시 결과에는 희귀도 전용 연출을 적용하지 않는다. 모션 감소 설정에서는 방사형 애니메이션을 숨기고 배너만 표시한다. 짧은 MP3는 단일 HTML 빌드에 포함하고 긴 지역 BGM만 외부 파일로 복사한다. 음원 경로와 출처는 `docs/AUDIO_ASSETS.md`를 기준으로 한다.

### `src/fish-dex.js`

저장된 `GAME_STATE.collections.fish`를 읽어 `전체 / 내륙 / 해안 / 원양` 대분류와 분류별 서식지 버튼, 발견 진행도, 다음 단계 보상, 발견 어종 통계와 미발견 출현 힌트를 렌더링한다. 전체 화면은 서식지별 접이식 구역이며 열린 구역의 카드만 생성한다. 15종 희귀어 힌트와 19종 마지막 단서 플래그에 따라 미발견 조건 공개 범위를 바꾼다. 발견한 어종은 `FISH_URLS`의 전용 픽셀 아트를 사용한다. 상세 정보는 중앙 팝업으로 열고 X·뒤로가기로 닫는다. 도감 열기·닫기 동안 공용 `menuOpen` 이동 잠금을 사용하며 발견 기록 자체는 변경하지 않는다.

### `src/data/tree-dex-data.js` / `src/tree-dex.js`

나무 50종의 설명과 `GAME_STATE.collections.trees`의 발견 기록을 사용한다. 나무를 완전히 벤 순간 수종을 처음 등록하고 이후에는 벤 횟수를 누적한다. 도감 탭은 `전체`, `새싹의 숲`, `거목의 경계`, `강철의 대삼림`, `정령의 성역`, `태초의 심연`만 같은 규격의 3열×2줄 고정 그리드로 표시하며 내부 단계 번호는 UI에 노출하지 않는다. 선택한 숲 끝에는 다음 숲의 이름과 나무 실루엣을 미리 보여 준다. 최초 발견 때만 밝은 3음 차임과 뒤집히는 카드를 표시하며 카드는 숲 이름·나무 이름·설명·`확인` 버튼만 보여 준다. 도감 목록은 나무 이름만, 상세는 숲 이름·설명·벤 횟수·XP·목재 판매가만 표시한다. 미발견 상세의 출현 지역·필요 도끼·발견 힌트와 발견 상세의 나무 체력은 표시하지 않는다. 기존 저장은 보유한 수종별 목재와 남아 있는 과거 벌목 상태에서 발견 기록을 보완한다.

세계 완료 마일스톤은 11/20/30/40/50종에 영구 꾸미기 보상을 지급한다. 순서대로 `새싹의 탐험가` 칭호, 청동 테두리, `대삼림의 벌목꾼` 칭호, 정령빛 효과, `세계수의 기록자` 칭호와 움직이는 황금 테두리다. `GAME_STATE.collections.treeMilestones`가 해금/확인 ID를 저장하며, 새 단계는 발견 카드 뒤에 보상 카드를 한 번만 표시한다. 기존 저장은 발견 수로 해금을 소급 계산하고 과거 카드는 확인 완료로 이행한다. 코인·목재·XP는 지급하지 않는다.

### `src/data/fishing-gear-data.js` / `src/fishing-gear.js`

낚싯대 6종의 사용 조건과 입질·희귀도·크기 보너스를 데이터로 선언한다. 엘리 상점에서 전체 목록과 잠긴 장비의 상세·구매 재료를 확인할 수 있다. 상점 구매는 보유 상태만 추가하며 실제 장착과 즉시 저장은 가방 장비 탭에서 수행한다. 월드 메뉴의 별도 낚싯대 장비 화면은 없다.

### `src/inventory.js`

`GAME_STATE.inventory`에 저장된 물고기를 어종별로 묶어 가방의 3열 이미지 카드로 표시한다. 보유 수는 이미지 오른쪽 위 배지에 표시하고, 물고기·재료 이름은 마우스 호버·키보드 포커스·모바일 터치로 확인한다. 원본 기록을 합치거나 삭제하지 않으므로 같은 어종의 개체별 크기·판매가는 상점 거래에서 사용한다. `재료` 탭은 씨앗·통나무·수확 작물을, 장비 탭은 보유한 모든 낚싯대·도끼를 보여 주며 클릭/터치로 장착한다. 가방은 X·취소·브라우저 뒤로가기로 닫을 수 있고, 가방에서 직접 판매하지 않는다.

### `src/market.js`

월드의 고정 상인 엘리를 바라보고 상호작용하면 상점을 연다. 물고기·통나무·작물은 종류별 수량을 선택해 판매하고, 씨앗 4종은 코인으로 구매한다. 어종별 수량 선택은 실제 인벤토리 순서(먼저 잡은 개체 우선)와 개체별 저장 가격으로 미리 계산한다. 확정 시 해당 수량만 차감하고 코인을 올려 즉시 저장한다. 저장 성공 후에만 돈 소리와 판매창·HUD 코인 증가, `+금액` 연출을 실행한다. 창을 닫으면 표시 숫자를 저장된 최종 금액으로 맞추며 모션 감소 환경에서는 즉시 반영한다. 저장 실패 시 인벤토리와 코인을 모두 롤백한다. 도감 통계는 판매해도 변하지 않는다.

엘리의 낚싯대 탭은 6종 전체를, 준의 도끼 탭은 10종 전체를 짧은 접기/펼치기 카드로 보여준다. 도끼 상점은 이미지·이름·가격·이전 도끼 보유 조건만 보여 주며 내부 피해량은 공개하지 않는다. 펼친 상세에는 필요 재료의 총량, 부족분, 구매 버튼을 표시한다. 구매 가능 여부는 기존 순차 구매·레벨·도감 조건으로 판단하며 도감 보상 낚싯대는 구매 버튼이 없다.

### `src/life-content.js`

벌목 나무의 단계별 체력·5분 재생, 수종별 목재와 나무 도감 기록 지급, 밭의 `LOCKED → EMPTY → GROWING → READY → EMPTY` 전환, 단계별 확장, 씨앗 소모·수확과 근접 밭 터치 UI를 담당한다. 작물은 `plantedAt`과 현재 시각의 차이로 성장하므로 오프라인 경과가 반영된다. 자원·코인·밭·나무·도감 변경은 기존 저장이 실패하면 함께 되돌린다.

### `scripts/process-fish-assets.py`

`assets/fishing/source/`의 생성 원본에서 투명 영역을 자르고 알파 가장자리를 정리한 뒤, 최근접 보간으로 96×96 게임용 PNG와 검토용 contact sheet를 만든다. 런타임과 단일 HTML 빌드는 정규화된 23개 파일을 참조한다.

### `src/save.js`

저장 버전 v1과 `localStorage` 입출력을 담당한다. 기존 낚시·코인·도감·장비 데이터에 현재 지역/위치, 벌목 나무 타격/재생 시각, 밭 확장·작물 심은 시각, 씨앗·통나무·수확 작물 수량을 가산해 형식 검증 후 복원한다. 이전 저장의 새 필드는 안전한 기본값으로 채운다. 과거 Lv.20 상한 저장의 누적 XP도 다시 계산해 Lv.21 이후 진행도로 복원한다. 저장 당시 장비가 현재 레벨·보상 기준으로 잠겨 있거나 ID가 유효하지 않으면 기본 낚싯대로 안전하게 되돌리며, 런타임 Activity 상태는 저장하지 않는다.

### `src/main.js`

에셋 준비 후 애니메이션 루프를 시작한다. 프레임마다 업데이트, 렌더링, 상황 문구 갱신을 순서대로 실행한다.

## 개발본과 배포본

- 개발본: 여러 소스와 이미지 파일을 사용하여 변경과 검토가 쉽다.
- 배포본: `node scripts/build.mjs`가 `dist/index.html` 하나로 합친다.

`dist/index.html`은 생성 파일이므로 직접 수정하거나 Git에 커밋하지 않는다.

### `src/world-time.js`

월드 전체가 공유하는 게임 시간과 시간대 판정, 시간대별 시각 보간값을 담당한다. 게임 1일은 현실 30분이며, 낚시·NPC·조명·날씨가 이 값을 읽고 각자 규칙을 적용한다.

### `src/weather.js`

6게임시간 단위 날씨 구간, 맑음·비·폭풍 확률, 하루 한 번 젖은 날씨를 보장하는 약한 보정과 개발자용 날씨 고정을 담당한다. 비·폭풍의 화면 효과는 렌더링 계층에서 그린다.

## 기능 추가 원칙

1. 기능 데이터와 규칙은 새 파일 또는 Activity Module에 둔다.
2. 이동·충돌·카메라 코어는 필요한 최소 범위만 변경한다.
3. 월드 상태를 변경하는 기능에는 저장 형식을 함께 정의한다.
4. 변경 후 `node scripts/check.mjs`와 `node scripts/build.mjs`로 구문, DOM 참조, 에셋, 배포 빌드를 확인한다.
5. 모바일 실기기에서 조이스틱과 화면 겹침을 최종 확인한다.
