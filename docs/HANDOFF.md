# Pixel Life 개발 인수인계

기준일: **2026-10-17**. 다음 세션은 이 문서와 [다음 콘텐츠 회의](NEXT_CONTENT_DISCUSSION_2026_10_17.md)부터 읽는다.

## 1. 바로 다음 작업

사용자는 새로운 콘텐츠 하나를 추가하고 싶어 한다. 광산·보물 탐사·동물 키우기·제작/요리를 논의했지만 **아직 선택하거나 구현을 지시하지 않았다.** 마지막 요청은 문서를 GitHub에 정리하고 다른 세션에서 이어가겠다는 것이다. 다음 세션에서 후보를 확정하고 첫 플레이 흐름을 설계한다. 어시스턴트가 보물 탐사를 추천한 것은 사용자 결정이 아니다.

현재까지 요청된 기능 수정과 공개 배포는 완료됐다. 새 콘텐츠의 구현을 자동으로 시작하거나, 이미 완성된 농사/주문/교환권/성장 현황을 다시 만드는 것은 다음 작업이 아니다.

## 4. 구현된 게임 범위

- 월드: 육지 18지역+어선 4지역=22지역, 각 64×48/48px 논리 타일. 마을·숲 12곳·농장·항구·산악 호수·폭포·늪이 왕복 연결된다.
- 마을: 상점 포함 건물 9채/주민 10명/8개 건물 크기 계열. 하루 상점은 마을 동쪽의 농장 가는 길 이전에 있다. 농장 안에는 하루/상점이 없다. 엘리는 물고기·낚싯대, 준은 목재·도끼, 하루는 씨앗·작물·주문·꾸미기를 담당한다.
- 벌목: 나무/그루터기/목재 50종, 도끼 10종, 부분 HP/5분 재생, 완전 벌목 시 목재 0~3개와 XP/도감, 발견·마일스톤·영구 꾸미기, 판매·수리·저장.
- 낚시: 물고기 74종·10서식지·낚싯대 10종, 지점/시간/날씨 풀·상대 Weight·3연속 보정, 입질 후 획득, 발견/크기/도감·졸업·영구 꾸미기. 기본 낚싯대와 Lv.1로 모든 어종의 장소/조건에 도전할 수 있다.
- 어선: 얕은/중간/심해/빙하 승선권 2,000/3,500/5,000/8,000코인. 앱 표시 중 10분 운항, 조기 귀항 가능/미환불. 진행 중 낚시가 만료되면 획득 확인/취소까지 보장한 뒤 항구로 돌아간다. 부표는 얕은 바다에만 있고 장식 간격/경계 진입·퇴장을 보완했다.
- 농사: 작물 14종·16칸 중 초기 4칸·지정 부지 영구 구매. 밭은 소유/심기 상태와 무관하게 항상 이동을 막고 통로에서 심고 수확한다. 기본 무한 낫·씨앗 소모·오프라인 성장·수확 XP·판매가 구현됐다. 심기 목록은 보유 씨앗만 표시한다.
- 농장 목표: 랜덤 주문 한 건 자동 지급→재배/수확→납품→코인/교환권→다음 한 건. 농사 레벨/보유 밭에 따른 주문 3단계, 교환권 소품 8종. 가방→농장 탭에 교환권/보유 소품/설치 상태를 표시하고 농장에서 설치·회수한다.
- 성장: 실제 활동은 낚시·벌목·농사 3종의 독립 Lv.1–100/이후 숙련도. 메타데이터·아이콘 총 7종 중 채집·채광·요리·수렵은 아직 활동 미구현이다. 공통 성장 v2의 Lv.100 누적은 187,230 XP다.
- 공통 표시: 최초 발견 카드 뒤 XP 연출, 수량 알림은 0개도 표시, 장비창/상세/하단 바에 내구도, 두꺼운 낚싯대 10종. 도구/일반 품목 구매·수리 성공 효과음, 물줄기/물보라 애니메이션.
- 미구현: 광산/보물 탐사/동물 사육/요리·제작/일반 의뢰/개인 주거·실내/상위 낫/전투. 기본 검의 외형과 휘두름은 있지만 몬스터·피해·사망은 없다.

## 5. 보호할 사용자 결정과 저장 계약

- 현재 저장 키 pixel-life.save.v2/버전 2. 보유 재화·장비/부분 또는 0 내구도·빈손·아이템·도감·작물/밭·주문/교환권/소품·운항·지역/위치를 유지한다. 과거 v1 초기화를 다시 실행하지 않는다. 거래/획득 저장 실패 시 전체 관련 변경을 복원한다.
- 기본 도끼/낚싯대/낫은 무한 내구도다. 유료 도끼는 실제 타격마다 나무 단계만큼, 유료 낚싯대는 저장 성공 획득 때 내륙/해안 1·바다 6/8/10/12만큼 마모한다. 낚시 취소는 무소모다.
- 0 내구도 장비는 소유권을 유지하지만 사용할 수 없다. 마지막 유효 타격/획득은 적용하고 빈손으로 저장한다. 정상 하위 도끼를 직접 선택해 대체 벌목한다. 부분 수리는 가능하고 구매/파손 수리 후 장착은 수동이다.
- 준의 구매 메뉴 귀환석은 100코인, 가방에서 1개 소모해 마을 중앙 (25,24)으로 간다. 저장 실패는 수량/위치까지 복원한다.
- 농사 핵심 목표는 쉽게 완성되는 작물 도감 대신 주문/납품/꾸미기로 정했다. 상위 낫·새 도감·집·전투·새 콘텐츠는 아직 확정하지 않았다. 기존 작물 재배에 새 레벨 잠금을 임의 추가하지 않는다.
- 독립 숲에는 번호를 붙이지 않는다. 고대 숲·정령 숲·태초 숲 등의 이름을 유지하고 여러 맵인 오래된 숲 1-1~1-5는 번호를 유지한다.
- NPC/플레이어·도구 손 위치·발 기준·검 동작·기존 음향을 임의 재생성하지 않는다. 새 캐릭터는 [NPC 규격](NPC_STANDARD_AUDIT_V1.md), [캐릭터 기준](CHARACTER_ASSET_STANDARD.md), [검 기준](SWORD_ACTION_STANDARD.md)을 따른다.
- 실제 Android 체감 검증은 사용자 결정으로 추후 확인한다. 자동 모바일 크기 검사를 실기기 성능/음량/손 조작 검증으로 표현하지 않는다.

## 6. QA·배포 기준

직전 게임 빌드 전체 검사: **53 runtime scripts / 150 UI IDs / 481 asset references / 74 fish**. 도구 스크립트 파일 수와 runtime scripts 수는 다르다.

공개 320/393px 모바일·PC 1280px에서 성장 현황·작은 HUD와 날씨를 검증했다. 날씨 수치 QA는 1만 게임 날짜와 5~60FPS의 실제 프레임 루프·백그라운드/복귀/BFCache를 검증한다. PWA는 새 캐시/설치 조건·강제 재로딩 없음·오프라인/음악 Range 206/100 bytes를 확인했다.

증거는 로컬 output/growth-status-qa, output/deploy-growth-status-qa, output/weather-qa, output/deploy-weather-qa에 있다. output 전체는 Git 제외이므로 새 컴퓨터에 없을 수 있다. GitHub에는 기준 문서·검사 코드·Actions 기록을 남긴다. 다른 세션에서 QA가 필요하면 관련 스크립트로 재현한다.

실제 저장은 일반 사용자 브라우저 대신 격리된 테스트 컨텍스트로 검증한다. 서버 주소/Playwright/Chrome 경로는 현재 환경에서 확인한다.

~~~text
git status --short
git fetch origin main
git rev-list --left-right --count HEAD...origin/main
node scripts/check.mjs
node scripts/build.mjs
git diff --check
~~~

문서만 변경했으면 링크/내용·빌드 불변을 검사하고, 게임 기능 변경 시 해당 회귀 검사를 선택한다. 전체 검사는 낚시 시뮬레이션 때문에 수분이 걸릴 수 있다. 통과한 동일 검사를 이유 없이 반복하지 않는다.

## 7. 새 세션 시작과 보존

로컬 변경을 먼저 확인한 뒤 원격을 가져와 비교한다. 원격이 앞서고 작업 폴더가 깨끗할 때만 필요한 fast-forward를 한다. 다른 세션의 변경/원화/첨부를 덮거나 강제 초기화하지 않는다.

dist는 생성 결과이며 직접 수정/커밋하지 않는다. 게임 배포는 HTML 외 BGM 3개와 PWA 파일을 포함한 dist 전체 8파일이다. 문서 푸시도 자동 게시되지만 게임 빌드가 같다면 전체 게임 화면 QA를 다시 확장할 필요는 없다.

현재 공개 배포 크기는 약 37.05MiB다. 전체 작업 폴더 용량과 구별하며 2026-10-12의 로컬 폴더 측정은 [용량 문서](PROJECT_STORAGE.md)의 과거 기록이다. 이번 문서 정리는 파일 정리/삭제 요청이 아니다.

QA 원화/프롬프트/음악·첨부·기준선·Git 기록을 보존한다. [QA 보존 정책](QA_RETENTION.md)·[보존 목록](QA_RETENTION_V1.json)을 따르며 새/정체불명 결과를 자동 삭제하지 않는다.

문서 전체 색인은 [docs/README.md](README.md), 실제 모듈 책임은 [ARCHITECTURE.md](ARCHITECTURE.md), 다음 회의는 [2026-10-17 논의 기록](NEXT_CONTENT_DISCUSSION_2026_10_17.md)을 따른다.
