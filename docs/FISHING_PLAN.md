# 낚시 Activity Module 계획

상태: 기획 초안

목표는 물가에서 시작해 물고기를 획득하고, 인벤토리와 보상에 반영되는 짧고 반복 가능한 첫 생활 콘텐츠를 만드는 것이다. 낚시에서 검증한 상호작용·보상·저장 구조는 이후 벌목과 채집에 재사용한다.

## 1. 권장 게임 루프

첫 버전은 복잡한 낚시 시뮬레이션보다 짧은 타이밍 게임으로 고정한다.

```text
물가 접근 → 조사/낚시 시작 → 찌 대기 → 입질 신호 → 제한 시간 내 액션
       → 성공: 물고기 획득 → 결과 표시 → 인벤토리/도감 반영
       → 실패: 물고기 놓침 → 물가로 복귀
```

### 기본 제안값

- 물가의 지정된 낚시 지점에서만 시작한다.
- 낚싯대와 미끼는 MVP에서 생략하고 플레이어가 기본 장비를 가진 것으로 처리한다.
- 찌 대기 시간은 1.5~4초 사이에서 무작위로 정한다.
- 입질 신호 후 0.85초 안에 액션하면 성공한다.
- 모바일은 큰 액션 버튼 탭, PC는 `Space`/`Z`/`Enter`를 사용한다.
- 이동하거나 취소 버튼을 누르면 낚시를 취소한다.
- 실패해도 체력·코인·내구도는 차감하지 않는다.
- 한 번에 한 마리만 획득하고, 결과 카드는 약 1초 뒤 닫힌다.

이 구조는 조작이 단순하면서도 “기다림 → 반응 → 보상”의 리듬을 만든다. 날씨, 시간대, 미끼, 장비 강화는 첫 버전에서 제외한다.

## 2. 낚시 상태

낚시 모듈은 이동 코어와 분리된 작은 상태 머신으로 만든다.

- `idle`: 낚시하지 않는 상태
- `casting`: 찌를 던지는 짧은 연출
- `waiting`: 입질 대기
- `bite`: 입질 신호와 제한 시간
- `result`: 성공/실패 결과 표시
- `cancelled`: 이동·취소로 종료

상태가 `waiting` 또는 `bite`인 동안에는 플레이어 이동을 잠시 잠그고, 대화·메뉴와 동시에 열리지 않도록 한다.

## 3. 첫 연못 물고기 목록 제안

처음부터 많은 종류를 만들지 않고 5종으로 시작한다. 수치와 이름은 기획 확정 전에 조정 가능하다.

| ID | 이름 | 등급 | 기본 등장 가중치 | 판매가 | 역할 |
|---|---|---:|---:|---:|---|
| `fish.pond_minnow` | 연못송사리 | common | 55 | 8 | 가장 흔한 기본 물고기 |
| `fish.willow_shiner` | 버들치 | common | 25 | 14 | 일반 보상 |
| `fish.crucian_carp` | 붕어 | uncommon | 13 | 24 | 중간 보상 |
| `fish.koi` | 잉어 | rare | 6 | 55 | 희귀 보상 |
| `fish.moon_scale` | 달빛비늘어 | special | 1 | 120 | 도감·희귀 연출용 |

가중치는 합계 100을 기준으로 하며, MVP에서는 물고기별 시간대·날씨 조건을 두지 않는다. 이후 지역이 늘어나면 지역별 테이블을 추가한다.

## 4. 물고기 데이터 규격

물고기 정의는 렌더링 코드가 아닌 별도 데이터 파일에 둔다.

```js
{
  id: 'fish.pond_minnow',
  name: '연못송사리',
  rarity: 'common',
  catchWeight: 55,
  sellPrice: 8,
  icon: 'fishPondMinnow',
  description: '라일락 연못에서 흔히 볼 수 있는 작은 물고기.'
}
```

권장 파일 위치:

- 데이터: `src/data/fishing.js`
- 모듈 상태/규칙: `src/fishing.js`
- 에셋 경로: `src/assets.js`의 낚시 에셋 그룹
- 이미지: `assets/fishing/`

## 5. 이미지·에셋 요구사항

### 물고기 아이콘

- 투명 배경 PNG
- 기준 캔버스 `96×96px`
- 실제 물고기는 중앙 70~80% 영역 사용
- 32~48px로 축소해도 실루엣과 색이 구분되어야 함
- 기존 Pixel Life의 따뜻한 픽셀 아트 팔레트와 동일한 광원 방향 사용
- 파일명은 영문 ID와 일치: `pond_minnow.png`, `willow_shiner.png` 등

### 낚시 연출 에셋

- `bobber.png`: 찌 기본 이미지, 투명 PNG
- `bobber_bite.png`: 입질 상태의 찌 또는 물결 강조
- `splash.png`: 성공/실패 공용 물튀김 효과
- 선택 사항: `rod.png` 또는 플레이어 손동작 프레임

MVP에서는 물고기 5장, 찌 2장, 물튀김 1장으로 시작한다. 물고기 스프라이트 애니메이션은 시스템이 검증된 뒤 추가한다.

## 6. 인벤토리·보상 규칙

- 물고기는 `itemId`와 `quantity`로 저장한다.
- 같은 물고기는 한 슬롯에 수량으로 쌓는다.
- MVP 인벤토리 용량은 24슬롯으로 제안한다.
- 가득 차면 낚시를 시작하지 않고 “가방이 가득 찼다”를 표시한다.
- 성공 시 물고기 수량과 도감 발견 횟수를 동시에 갱신한다.
- 판매 기능은 낚시 MVP와 분리하고, 상점 Activity에서 연결한다.

저장 데이터에는 최소한 다음을 포함한다.

```js
{
  saveVersion: 1,
  inventory: [{ itemId: 'fish.pond_minnow', quantity: 1 }],
  collections: { 'fish.pond_minnow': 1 }
}
```

## 7. 구현 순서

1. 기획값 확정: 낚시 방식, 물고기 5종, 성공 판정 시간, 실패 규칙
2. 물고기 데이터 파일과 에셋 규격 확정
3. `idle → casting → waiting → bite → result` 상태 머신 구현
4. 모바일 액션 버튼과 PC 키 입력 연결
5. 결과 카드와 물고기 아이콘 표시
6. 최소 인벤토리·도감 갱신 구현
7. 저장/불러오기와 버전 필드 연결
8. 연못 실기기 QA 및 PC 키보드 QA
9. 성공 후 벌목에 공용 자원 획득 인터페이스 재사용

## 8. MVP에서 하지 않을 것

- 낚싯대 등급과 내구도
- 미끼 종류
- 날씨·시간대별 어종 변화
- 물고기별 별도 미니게임
- 상점 판매와 요리 연계
- 여러 연못의 독립 낚시 테이블

위 항목은 낚시 루프가 재미있고 안정적인지 확인한 뒤 2차 콘텐츠로 추가한다.

## 9. 완료 기준

- 모바일에서 물가 진입부터 획득 결과까지 한 사이클이 자연스럽게 동작한다.
- PC에서 동일한 사이클을 키보드로 수행할 수 있다.
- 성공·실패·취소 상태가 서로 섞이지 않는다.
- 획득한 물고기가 인벤토리와 도감에 반영된다.
- 새로고침 후에도 획득 결과가 유지된다.
- `node scripts/check.mjs`, `node scripts/build.mjs`가 통과한다.
