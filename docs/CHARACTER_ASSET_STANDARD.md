# 캐릭터·외형·무기 제작 고정 기준

규격 ID: `npc-compatible-v1` · 기준 코드: `edb9c9d` · 작성일: 2026-09-27

## 1. 가장 중요한 원칙

**새 에셋을 공통 틀에 맞춘다. 새 에셋 때문에 기존 캐릭터·옷·가방·무기·모션을 다시 맞추지 않는다.**

이 문서는 앞으로의 제작 기준이다. 과거 제작 이력이 섞인 CHARACTER_APPEARANCE.md보다 우선한다. 좌표의 최종 원본은 src/data/character-rig-data.js이며 추측으로 좌표를 다시 만들지 않는다.

현재 일반 게임과 시험 보정은 별도로 유지한다. 시험 링크의 보정 동작을 새 제작물의 시각 검토 기준으로 삼되, 규격 확정이 일반 게임 적용 승인은 아니다. 기본 승격은 별도 사용자 승인 후 진행한다.

2026-09-27 승인된 부분 승격: **아래 걷기 공통 x 정렬만** 일반 게임에 적용했다. 시험 original은 이전 정렬 비교용이다. 새 의상 원화와 도끼날 투영은 여전히 시험 전용이다. character-standard-v1.json의 approvedPromotions에 이전 renderer hash와 범위를 기록하고 해당 renderer hash만 갱신했다. 에셋/geometry/도구 기준은 변경하지 않았다.

2026-09-27 후속 의상 수정: 일반 게임도 기존 npc-wardrobe-v2 불꽃/정원복을 사용한다. 가방/상세/NPC 미리보기는 실제 장착 그림을 따른다. 시험 original만 옛 의상을 비교하고 앞뒤 도끼날 보정만 기본 승격 대기다. 이번에는 renderer/geometry/도구/PNG 기준을 바꾸지 않고 연결·아이콘 선택만 수정했다. 현재 기준은 이 후속 기록을 우선한다.

2026-09-27 시험 비교 추가: `?walk-preview`의 `흔들림 완화`는 아래 걷기 공통 x 이동만 [0,+2,-1]로 시험한다. 일반 게임 [0,+3,-2]와 고정 제작 시트/rig는 유지한다. 시험을 위한 renderer 변경은 character-standard-v1.json의 trialChanges에 기록했고 승인된 기본 동작 변경은 아니다.

2026-09-27 목 연결 후속 시험: 위 시험 경로의 머리/헤어만 [0,-1,+1]로 맞춰 현재 승인 동작과 같은 머리↔옷깃 상대 정렬을 보존한다. 일반 게임·기준 시트·rig/geometry는 변경하지 않는다. trialChanges에 renderer 변경 이력을 추가했고 실기기 사용자 확인 전 일반 적용하지 않는다.

자동 검사를 통과해도 미술 품질까지 자동 보장되지는 않는다. 새 원화가 틀에 맞지 않으면 해당 새 원화를 고치거나 반려한다. 기존 공통 틀을 몰래 변경하지 않는다.

## 2. 고정 규격

| 항목 | 고정 기준 |
| --- | --- |
| 게임용 셀 | 투명 PNG, 96×96px |
| 화면 표시 | 셀 100×100px, 동작/성별/장비별 확대 금지 |
| 발 기준 | 셀 (48,88), 월드 위치·충돌 기준 불변 |
| 목 기준 | (48,54), 목부터 발까지 현재 NPC 체형 공유 |
| 방향 행 | 아래 → 오른쪽 → 왼쪽 → 위 |
| 걷기 시트 | 288×384px, 3프레임×4방향 |
| 벌목/허공 시트 | 192×384px, 2프레임×4방향 |
| 낚시 시트 | 288×384px, 3프레임×4방향 |
| 전체 자세 | 32개, 누락 허용 안 함 |
| 걷기 박자 | 0→1→2→1, 105ms; 정지0 |
| 벌목 박자 | 준비→270ms 타격→700ms 종료 |
| 주 손 | 오른손, 프레임별 grip/가림은 기존 rig 값 그대로 |
| 무기 PNG | 96×96px, 실손잡이 grip·끝점 tip·축각·축길이 등록 |

아래 걷기 x=[0,+3,-2]px는 일반 게임의 공통 렌더러가 몸/옷/가방/손/무기에 함께 적용한다(시험 original은 예전 무보정). 새 시트에 이 이동을 미리 그려 넣거나 에셋마다 중복 offset을 추가하지 않는다. 앞뒤 도끼날의 0.55폭 투영/반전도 공통 렌더러에 맡긴다.

## 3. 종류별 제작 규칙

### 새로운 사용자 캐릭터·헤어

- 이 규격에서 남녀·추가 캐릭터는 같은 Body/Grip을 사용한다. 얼굴과 헤어는 교체 가능하지만 몸/팔길이/손/발 위치를 바꾸지 않는다. 외형 교체 가능한 NPC도 이 틀로 제작하며 기존 고정 NPC 그림을 자동 변환하지는 않는다.
- 얼굴과 헤어를 합친 완성 머리를 기준 목 위치에 한 번 등록한 뒤 같은 좌표에서 Head/Hair를 분리한다. 둘을 따로 바운딩박스에 꽉 채워 확대하지 않는다.
- 머리에는 옷/가방/손/무기 픽셀을 포함하지 않는다. 사방향 중립 머리를 각 동작 프레임에 같은 크기·위치로 유지한다. 벌목의 이동/회전은 기존 headMotion이 수행한다.
- 서로 다른 헤어와 얼굴 조합에서 뒤통수 노출·목 연결·머리 가림을 확인한다. 셀 크기만 같다는 이유로 호환 완료라고 판단하지 않는다.
- 앞/옆 중립 Head는 공통 Body의 목깃 중앙(x39~57, y50~60)과 픽셀로 겹쳐야 한다. 자동 기준은 앞 최소10픽셀, 좌우 최소5픽셀이다. 뒤 방향은 헤어/가방 가림 때문에 이 단순 수치 대신 실제 합성을 확인한다. 새 머리를 단순 축소해 피부 연결을 잃지 않는다.

### 새로운 옷

- 제작 템플릿: assets/player/npc-v1/{walk,chop,fish}-outfit.png. 몸과 손 참고: 같은 경로의 -body.png / -grip.png. 작은 예전 체형 원화나 게임 스크린샷을 제작 틀로 쓰지 않는다.
- 현재 규격은 몸에 맞는 상의·바지·신발을 하나의 Outfit으로 교체하는 방식이다. 프레임별 템플릿 alpha(외곽선/목/손 노출)를 정확히 유지한다. 디자인·색·깃·소매·주머니·천 질감은 새로 그리되 해부학적 위치는 바꾸지 않는다.
- 머리/피부/손/가방/무기를 옷에 합쳐 넣지 않는다. 기본 파란 옷 위에 새 옷을 부분적으로 덮는 방식도 금지한다. 방향별 앞장식/뒷면/소매가 같은 디자인인지 검토한다.
- 세 시트를 모두 제공한다. 현재 몸과 옷의 왼쪽 행은 오른쪽의 반전 규약을 따른다. 비대칭 의상은 현재 규약에서 완전 지원한다고 가정하지 않는다.
- 긴 치마·망토·부풀린 외곽·분리 상하의는 현재 고정 alpha 밖의 기능이다. 필요한 경우 별도 규격 확장을 제안하되 기존 fitted 의상 틀은 유지한다.
- 새 AI 원화는 초안이다. 패킹 전에 기준 자세와 실제로 맞는지 검토한다. 큰 오차를 기존 몸 확대나 강제 늘이기로 숨기지 않는다. pack-npc-wardrobe-v2.mjs는 현재 두 옷의 재현 스크립트이며 모든 미래 원화에 무검토 적용하는 도구가 아니다.

### 새로운 가방

- 프레임별 기존 등/어깨 위치에 **전체 가방 실루엣**을 부착한다. 머리 위치에 붙이거나 잘린 가방 조각을 복사하지 않는다.
- 기준 참고: assets/player/npc-v1/{walk,chop,fish}-backpack.png와 현재 ranger/berry 시트. scripts/lib/character-attachments.mjs는 보호된 과거/공통 부착 도구이며 새 몸에 맞춘 최종 부착은 현재 npc-v1 프레임을 우선한다.
- 정면에서는 현재처럼 가방이 가려진다. 옆/뒤에서 몸 alpha와 최소4픽셀 겹치고 셀 경계를 넘거나 닿아 잘리지 않아야 한다. 측면에서는 몸 뒤 가림을 사용한다.
- 손/머리/옷을 가방 파일에 넣지 않는다. 시트3개·32자세 및 목/팔/가방 연결을 실제 합성에서 확인한다.

### 새로운 도끼·낚싯대

- 무기만 투명 PNG로 제작한다. 캐릭터나 손을 함께 그리지 않는다. 상점용 큰 아이콘은 별도이며 게임에서 쥐는 PNG와 혼용하지 않는다.
- 무기 자체의 실제 grip/tip을 측정해 nativeLength=두 점의 거리, nativeAngle=grip→tip의 각도로 등록한다. 다른 무기의 metadata를 무조건 복사하지 않는다.
- 공통 손 좌표·길이·회전·반전·날 폭 투영·가림을 사용한다. 새 무기 때문에 손 위치/캐릭터 크기/기존 무기 각도를 바꾸거나 무기 ID별 예외를 렌더러에 추가하지 않는다.
- 낚싯줄은 공통 tip→찌 렌더러가 그린다. 원화에 고정된 긴 낚싯줄을 남기지 않는다.
- 현재 지원 동작군은 axe/rod다. 검·창·활 등의 다른 동작은 이름/PNG 추가만으로 지원되지 않는다. 새 pose와 호환 규격을 별도 버전으로 설계한다.

## 4. 제작물 납품·등록 순서

1. 규격 ID와 종류를 먼저 정하고 현재 기준 템플릿을 제공한다.
2. 새 원화와 세 동작 시트(무기는 PNG+grip/tip metadata)를 제작한다. 이름/새 ID/원본/제작 기록을 함께 보존한다.
3. 좌표·셀·alpha·공통 부품 연결을 검사한다. 불합격이면 새 에셋만 수정한다.
4. 새 경로와 ID를 assets/config 또는 rig의 tools에 등록한다. 기존 소유/착용 ID·저장/레벨/돈을 재설정하지 않는다. 기존 에셋 경로 덮어쓰기 금지.
5. 새 품목을 실제 검사 목록에 포함해 모든 성별/보유 옷/가방/방향/자세 조합을 검사한다. 기존 576개 통과는 미래에 추가한 품목의 통과를 뜻하지 않는다. 품목 증가 시 조합 수와 기존 고정 개수 검사를 함께 갱신한다.
6. 실제 걷기/낚시/벌목/허공·착용/상세·재접속·저장 실패 복원을 검사하고 Android 화면에서 시각 확인한다.
7. 시험 링크에서 확인을 받은 뒤 기본 게임 등록/배포한다. 시험 선택과 실제 장착 저장은 구분한다.

## 5. 자동 보호와 검증

docs/character-standard-v1.json은 기준 시점의 공통 pose 좌표와 기존 도구 metadata, 기존 PNG·렌더러·부착 도구 해시를 보존한다. 텍스트 해시는 LF로 정규화해 Windows/Linux 양쪽에서 일치한다.

scripts/check-character-standard.mjs는 등록된 일반/시험 의상과 body/head/hair/bag, 모든 axe/rod를 읽어 검사한다. 새로운 tools 항목과 새로운 경로/ID 등록은 허용하되 기존 좌표/도구/원본 변경은 실패시킨다. scripts/check.mjs에 연결했으므로 기존 Pages의 Validate source 단계에서도 실행된다.

```bash
node scripts/check-character-standard.mjs
node scripts/qa-character-standard.mjs
node scripts/check.mjs
node scripts/build.mjs
```

브라우저 검증은 qa-npc-character / qa-npc-wardrobe-v2 / qa-character / qa-walk-preview / qa-axe-facing-preview / qa-inventory-ui / qa-held-tool을 품목 목록에 맞춰 실행한다. Playwright·Chrome 경로 설정은 기존 QA 문서/스크립트를 따른다. 기계검사 외에 느린 실제 합성 영상·사방향 확대·폰 플레이 확인이 필요하다.

보호 파일 해시나 geometryHash를 검사를 통과시키려고 자동 갱신하지 않는다. 공통 틀을 바꿀 명확한 필요가 생기면 사용자 승인→새 버전→기존 호환/회귀 검증→변경 기록 순서로 진행한다. 시험 보정의 기본 승격도 별도 승인 후 의도적으로 기준을 갱신하고 회귀 검사를 수행한다.

## 6. 완료 판정과 한계

같은 체형·같은 동작군의 추가 에셋은 **새 그림과 등록 데이터만** 바꿔 완료하는 것이 목표다. 공통 캐릭터/기존 의상/기존 무기/모션 수정이 필요하다면 아직 규격 호환 품목으로 납품된 것이 아니다.

이 규격은 재보정의 원인을 줄이고 잘못된 등록을 막지만, 모든 미래 디자인이 수정 없이 성공한다는 보장은 아니다. 호환되지 않는 새 원화는 새 원화만 보정한다. 새로운 체형·동작·레이어 기능은 사용자와 합의한 확장 작업으로 다룬다.
