# 낚시 74종 확장 설계

상태: **확정 로스터를 바탕으로 한 구현 전 설계**  
정리일: 2026-10-07

이 문서는 외부에서 전달된 `낚시 확장 로스터 (확정안 · 2026-10-06)`을 현재 게임의 20종 낚시, 6종 낚싯대, 도감, 저장, 월드 구조에 맞춘 확장 기준이다. 기존 동작의 현재 기준은 [`FISHING_PLAN.md`](FISHING_PLAN.md)를 함께 따른다. 이 문서에 적힌 확장 항목은 아직 게임에 구현됐다는 뜻이 아니다.

## 1. 확정 범위

- 최종 로스터는 **10개 서식지, 총 74종**이다.
- 기존 20종은 ID·발견 기록·보유 개체·크기 기록을 유지한다.
- 신규 어종은 **54종**이다.
- 등급은 `common / uncommon / rare / heroic / legendary` 다섯 단계로 유지한다.
- 입질 뒤에는 100% 획득한다. 실패, 줄 끊김, 타이밍 미니게임은 추가하지 않는다.
- 낚싯대는 입질 대기, 희귀 이상 상대 Weight, 큰 개체 확률을 개선하되 시간·날씨·서식지 조건을 무시하지 않는다.
- 낮은 낚싯대도 접근 가능한 물가라면 모든 어종을 잡을 가능성이 있다. 특정 낚싯대로 어종을 절대 차단하지 않는다.
- 지역 해금은 월드 탐험과 항구 노선 개방으로, 원양 출항은 목적지별 승선권으로, 어종 출현은 서식지·시간·날씨로, 장비 성장은 낚시 효율로 역할을 분리한다.

### 3.1 항구 승선과 제한 시간

플레이어가 배를 직접 건조하거나 조종하지 않는다. 마을 항구의 매표소 또는 선장에게서 목적지별 승선권을 사고, 항구에서 목적지를 선택해 유료 낚싯배에 승선한다. 배 위에서는 다른 목적지로 바꿀 수 없으며 다음 항해도 다시 항구에서 선택한다.

앞서 정한 어선 체험은 그대로 유지한다.

- 마을 항구 월드에 실제 정박한 배·선장·매표소를 배치한다.
- 목적지 선택과 승선권 처리가 끝나면 짧은 승선·출항 연출 뒤 전용 갑판 맵으로 전환한다.
- 갑판 안에서 캐릭터가 걸어 다니고 여러 난간 낚시 지점에서 기존 연못과 같은 조작으로 낚시한다.
- 난간 위치가 여러 개여도 한 항해 안에서는 모두 같은 목적지 어종 풀을 사용한다.
- 갑판의 기본 구조와 충돌은 네 목적지가 공유하고, 바다·수평선·날씨·음악·환경 소품을 목적지별로 바꾼다.
- 얕은·중간·심해·빙하는 각각 별도 지역 ID로 관리해 저장·효과음·배경·어종 풀이 섞이지 않게 한다.
- 조타 장치는 목적지 선택 UI로 사용하지 않는다. 조기 귀환이 필요하면 선장이나 귀환용 종처럼 목적지가 바뀌지 않는 별도 상호작용을 사용한다.
- 긴 바다를 직접 운전하는 조작은 넣지 않는다. 추후 무인도·해상 보물·바다 몬스터처럼 항해 자체가 콘텐츠가 될 때 별도 기능으로 검토한다.

- 승선권은 `얕은 바다 / 중간 바다 / 심해 / 빙하 해역` 네 종류다.
- 코인을 내고 여러 장을 미리 살 수 있으며 가방 재료 탭에서 수량을 확인한다.
- 승선권은 구매할 때가 아니라 해당 목적지로 **출항할 때 1장** 소모한다.
- 저장이 성공한 뒤에만 승선권을 차감하고 어선 맵으로 이동한다. 실패하면 수량·코인·위치를 모두 되돌린다.
- 상위 노선의 해금 조건은 낚시 진행과 월드 퀘스트로 정하며 낚싯대 단계나 전설어를 필수 조건으로 삼지 않는다.
- 승선권 가격과 운항 시간은 신규 어종의 분당 판매가를 시뮬레이션한 뒤 확정한다.
- 자발적으로 일찍 귀환해도 사용한 승선권은 돌려주지 않는다.

운항 시간은 **앱 화면이 실제로 보이는 동안만** 감소한다. `document.visibilityState`가 `hidden`인 백그라운드·화면 잠금·앱 전환 시간은 빼고 남은 시간을 저장한다. 게임 메뉴나 낚시 결과창이 열려 있어도 앱이 보인다면 시간은 계속 흐른다.

운항 시간이 0이 되면 `returnPending` 상태가 된다.

- 낚시 중이 아니면 즉시 마을 항구로 자동 귀환한다.
- 캐스팅·대기·입질·획득·결과 확인 중이라면 현재 한 번을 강제로 끊지 않는다.
- 플레이어가 물고기를 잡고 결과창을 닫거나 `낚시 취소`로 그 시도를 끝내는 즉시 항구로 귀환한다.
- 시간이 끝난 뒤에는 새 낚시를 시작할 수 없다.
- 종료 직전에는 1분·10초 안내를 제공하되 낚시 버튼이나 결과창을 가리지 않는다.

### 3.2 계속 달리는 어선 연출

갑판·캐릭터·낚시 지점은 안정적으로 유지하고 바다와 먼 풍경이 계속 뒤로 흐르게 해 실제 항해처럼 보이게 한다. 하나의 동일한 바다 타일을 짧게 반복해서는 안 된다. 거대한 고정 맵을 만드는 대신, 손으로 만든 작은 장면 조각을 실행 중 조합하고 화면 밖 조각을 새 조합으로 교체한다.

화면은 다음 네 계층으로 구성한다.

1. 먼 수평선: 구름, 섬, 배, 빙산처럼 천천히 움직이는 풍경
2. 중간 바다: 큰 파도, 부표, 암초, 물고기·고래 그림자
3. 가까운 바다: 빠르게 지나가는 물결, 반사광, 파편과 거품
4. 고정 갑판: 난간, 캐릭터, 낚시 지점과 배의 항적

각 목적지는 별도 장면 풀을 사용한다.

- 얕은 바다: 밝은 물, 산호 암초, 작은 섬, 갈매기, 부표
- 중간 바다: 넓은 수평선, 큰 파도, 먼 화물선, 돌고래
- 심해: 짙은 수면, 먹구름, 거대한 그림자, 발광 생물
- 빙하 해역: 유빙, 빙산, 눈보라, 푸른 얼음, 오로라빛 하늘

반복이 눈에 띄지 않도록 장면 생성에는 다음 계약을 둔다.

- 바탕 물결, 파도 무늬, 중경 물체, 원경, 날씨 효과를 독립적으로 조합한다.
- 바로 앞 장면과 같은 주요 바탕·랜드마크 조합을 금지한다.
- 최근 여섯 장면과 동일한 `sceneSignature`는 다시 선택하지 않는다.
- 랜드마크 없이 물결만 흐르는 구간과 큰 사건이 지나가는 구간을 섞어 과밀함도 피한다.
- 조각의 길이와 등장 간격을 조금씩 달리해 일정한 반복 박자를 숨긴다.
- 이동 중인 바다 조각은 화면에 필요한 수만 유지하고, 화면 밖에서 다음 조각을 미리 합성해 모바일 메모리와 프레임을 보호한다.
- 갑판 전체를 크게 흔들지 않고 바다·항적·원경의 상대 이동으로 속도를 표현한다. 모션 감소 설정에서는 흔들림과 빠른 근경 이동을 줄인다.

## 5. 월드와 낚시터 구조

현재 코드는 지역 ID 하나를 서식지 하나에 대응한다. 확장 뒤에는 같은 맵 안의 강, 폭포 소, 호수처럼 서로 다른 물가가 공존할 수 있으므로 **지역 기준이 아니라 낚시 지점 기준**으로 바꾼다.

낚시 시작 시 다음 문맥을 고정한다.

```text
regionId + spotId + habitat + period + weather
```

- 각 낚시 가능 물가 또는 물가 구역에 `fishingHabitat`을 둔다.
- 캐스팅 뒤 지역·시간·날씨가 바뀌어도 해당 시도의 문맥은 시작 시점 값으로 유지한다.
- 기존 지역 매핑은 이전 맵의 기본값으로 남겨 저장과 디버그 호환을 돕는다.
- 어선에서는 항구에서 확정한 목적지가 `boat_shallow`, `boat_mid`, `boat_deep`, `glacier` 중 하나의 서식지가 된다. 갑판의 낚시 지점은 모두 해당 항해의 같은 풀을 사용한다.
- `temporaryAllFishAtVillagePond`는 필요한 월드가 열리기 전까지 유지하고, 연못·강·해안의 실제 접근과 저장 복원을 검증한 배포에서만 끈다.

## 6. 데이터 계약

어종 설명을 `fish-dex.js`의 별도 객체에 계속 늘리지 않고 어종 데이터에 합친다.

```text
id, name, asset, habitat, rarity,
periods, weather,
minSizeCm, maxSizeCm,
basePrice, xp, weight,
description, introducedVersion
```

규칙:

- `id`와 `asset`은 전체 74종에서 유일해야 한다.
- 기존 20종 ID는 바꾸지 않는다.
- 시간·날씨 조건 없음은 빈 배열이 아니라 현재와 같은 `null`을 쓴다.
- 표시명과 설명은 데이터에 두고 도감·결과·상점이 같은 값을 읽는다.
- 서식지 라벨과 정렬 순서는 별도 메타데이터 한곳에서 관리한다.
- 어종 배열의 위치를 저장 식별자로 사용하지 않는다.

## 7. 출현 확률과 밸런스 원칙

초기 Weight 범위는 다음 구간에서 시작하되, 실제 값은 시뮬레이터로 확정한다.

| 등급 | 초기 Weight 범위 | 조건 충족 시 기본 낚싯대의 목표 체감 |
| --- | ---: | --- |
| 일반 | 28~36 | 풀의 중심 |
| 고급 | 14~20 | 자주 보이지만 일반보다 적음 |
| 희귀 | 5~8 | 여러 번 낚으면 만날 수 있음 |
| 영웅 | 1.5~2.5 | 조건을 노리고 오래 찾는 대상 |
| 전설 | 0.4~0.8 | 조건이 맞아도 장기 목표 |

- Weight는 퍼센트가 아니다. 현재 조건으로 필터링한 풀의 Weight 총합과 낚싯대 보정을 적용한 최종 확률을 따로 계산한다.
- 모든 서식지는 어느 시간·날씨에서도 최소 한 종이 남아 100% 획득 규칙을 지켜야 한다.
- 같은 어종 3회 연속 보정은 유지한다.
- 희귀도 보너스는 `rare/heroic/legendary`의 Weight에만 적용하며 조건을 새로 만족시키지는 않는다.
- 전설어를 일반 진행이나 배 업그레이드의 필수 재료로 사용하지 않는다.
- 신규 가격은 서식지 번호만 보고 배수로 정하지 않는다. 대기시간, 이동시간, 조건 대기, 낚싯대 보너스, 판매까지의 왕복을 포함한 시간당 코인으로 비교한다.
- 평균 진행에서 빙하 첫 진입과 최종 낚싯대 준비가 Fishing Lv.100보다 먼저 오게 한다. Lv.100은 모든 지역을 연 뒤에도 계속 낚는 장기 목표다.

최소 자동 계산 결과에는 서식지·낚싯대별 다음 값이 포함돼야 한다.

- 조건별 최종 어종 확률
- 전설어 1회 발견까지의 평균·중앙·상위 90% 시도 수
- 분당 XP와 분당 판매가
- 장비 구매 재료를 모으는 평균 시도 수
- 74종 도감 완성의 대략적인 진행 구간

## 8. 낚싯대와 내구력 확장

현재 6종의 ID와 소유 상태는 유지한다. 목표 10단계에서 신규 4종의 이름·가격·재료는 확률 시뮬레이션과 신규 그림을 함께 본 뒤 확정한다.

| 단계 | 상태 | 역할 |
| ---: | --- | --- |
| 1~4 | 기본·튼튼한·강철·전문가 낚싯대 구현됨 | 초반 대기·희귀도·크기 성장 |
| 5 | 강태공의 낚싯대 구현됨 | 20종 도감 보상 유지 |
| 6 | 심해 낚싯대 구현됨 | 현행 최상위 효과와 저장 ID 유지 |
| 7 | 신규 예정 | 원양 초반의 대기시간 개선 |
| 8 | 신규 예정 | 악천후·영웅 어종 탐색 효율 개선 |
| 9 | 신규 예정 | 심해 장기 파밍과 큰 개체 개선 |
| 10 | 신규 예정 | 빙하 이후 상징 장비, 전설 확률은 과도하게 올리지 않음 |

장비가 10종이 되더라도 상위 물고기 접근을 낚싯대 단계로 막지 않는다. 배와 월드 진입이 장소를 열고, 낚싯대는 그 장소에서의 시간과 결과 품질을 개선한다.

낚싯대 내구력은 74종과 신규 지역이 안정된 뒤 별도 단계로 적용한다.

- 기본 낚싯대는 무한 내구도다.
- 유료 낚싯대는 물고기 획득이 확정된 시도에서만 1회 감소한다.
- 투척 직후 취소, 메뉴 닫기, 결과창 확인에는 추가 감소가 없다.
- 0이 되면 장비는 사라지지 않고 자동 해제되어 빈손이 된다.
- 마을에서 부분 손상 상태도 언제든 수리할 수 있다.
- 수리 후 자동 장착하지 않는다.
- 저장 실패 시 물고기·XP·내구도·장착 상태를 함께 되돌린다.

## 9. 도감 구조와 보상

74종을 한 줄 탭 11개로 만들지 않는다. 모바일에서 가로 스크롤 없이 다음 두 단계로 탐색한다.

1. 상단 분류: `전체 / 내륙 / 해안 / 원양`
2. 하단 서식지 버튼: 선택한 분류의 서식지만 최대 3열 그리드로 표시

- 내륙: 연못, 강, 산악 호수, 폭포, 늪지
- 해안: 바다
- 원양: 얕은수심, 중간수심, 심해지역, 빙하
- 전체 화면은 서식지별 접힌 구역과 진행 수를 보여 주며 74장을 한꺼번에 길게 렌더링하지 않는다.

기존 5/10/15/19/20종 보상과 이미 지급된 저장 플래그는 유지한다. 20종 이후는 경제를 흔들지 않는 영구 외형 보상을 우선한다.

| 발견 수 | 확장 보상 방향 |
| ---: | --- |
| 30종 | `물길 탐험가` 칭호 |
| 40종 | 물결 도감 테두리 |
| 50종 | 어선 깃발 장식 |
| 60종 | `심해 탐사자` 칭호 |
| 74종 | `세계의 강태공` 칭호와 움직이는 오로라 테두리 |

보상 명칭과 그림은 구현 시 최종 승인한다. 코인·XP·필수 장비는 20종 이후 전역 마일스톤에 넣지 않는다.

각 서식지를 모두 발견하면 다음을 지급한다.

- 서식지 도장 1개
- 최초 1회 졸업 카드
- 도감 해당 구역의 작은 영구 장식

서식지 졸업은 다음 지역 입장의 필수 조건이 아니다. 마지막 미발견 단서는 전역 1종이 아니라 **선택한 서식지에서 1종이 남았을 때** 동작하도록 확장한다.

## 10. 저장 이행

- 기존 `collections.fish[fishId]` 기록은 그대로 사용한다.
- 기존 인벤토리의 물고기 개체와 가격을 재계산하거나 삭제하지 않는다.
- `fish.coelacanth`는 ID를 유지한 채 서식지만 `coast`에서 `boat_deep`으로 이동한다. 기존 발견 기록과 보유 개체는 남는다.
- 기존 20종 보상을 받은 저장은 회수하지 않는다.
- 새 전역 보상과 서식지 보상은 별도 플래그로 저장한다.
- 기존 저장이 이미 새 기준 수량을 충족하면 외형은 소급 해금하되 과거 보상 카드를 연속 재생하지 않는다.
- 해금된 항구 노선과 목적지별 승선권 수량을 별도 진행 데이터로 저장한다.
- 운항 중에는 `destination`, `remainingMs`, `returnPending`, 장면 조합용 `tripSeed`를 저장한다. 백그라운드 경과 시간은 `remainingMs`에서 빼지 않는다.
- 운항 종료 상태로 재접속하면 항구로 복원하고, 운항 시간이 남았다면 같은 목적지 갑판과 남은 시간을 복원한다.
- 삭제되거나 알 수 없는 어종 ID 때문에 전체 저장 불러오기가 실패하지 않도록 유효 항목만 복원한다.

- `temporaryAllFishAtVillagePond`를 끈 뒤 마을 연못에는 연못 어종만 나온다.
