# Pixel Life Architecture

## 목표

이 프로젝트는 코어 시스템을 안정적으로 유지하면서 생활 콘텐츠를 독립적인 Activity Module로 추가하는 것을 목표로 한다.

생활 스킬 성장의 확정 설계 기준은 [`LIFE_SKILL_PROGRESSION.md`](LIFE_SKILL_PROGRESSION.md)이다. 현재 낚시에는 Lv.1–100·이후 숙련도와 공통 스킬 데이터·UI가 첫 적용되었다. 다른 생활 스킬의 실제 행동·저장 연결은 후속 작업이다. Lv.21 이후 요구량은 임시 밸런스다.

```text
입력 → 시뮬레이션 → 월드 상태 → 렌더링
              └────→ 상호작용/UI
```

## 파일 책임

### `src/assets.js`

개발용 이미지 경로만 관리한다. 월드·캐릭터·건물과 `FISH_URLS`의 20종 물고기 경로를 한곳에서 선언한다. base64 데이터는 소스에 직접 넣지 않으며 `npm run build` 단계에서만 단일 HTML에 포함한다.

### `src/config.js`

Canvas, 프로젝트 메타데이터, 지역 및 Activity Module 목록, 공용 게임 상태와 에셋 로딩을 담당한다. 필수 월드 에셋은 병렬로 로드하고, 플레이어 정규화 시트가 실패했을 때만 레거시 프레임을 불러온다.

### `src/data/world-map.js`

맵 크기, 플레이어 시작점, 지형 구간, 건물, NPC, 고정 오브젝트와 장식을 선언하는 단일 배치 데이터 소스다. 새 월드 콘텐츠는 렌더링 코드가 아니라 이 파일 또는 같은 규격의 지역 데이터 파일에 추가한다.

### `src/world.js`

월드 정의를 읽어 타일 Set, 충돌 데이터와 런타임 엔티티를 구성한다. 시각 표현을 바꾸더라도 이동용 타일 데이터는 가능한 한 유지한다.

### `src/world-validation.js`

월드 크기, 좌표, ID, 건물 footprint, 문과 접근 타일, 물 겹침, NPC 시작 위치를 검사한다. 오류가 있으면 게임 시작과 빌드 검사를 실패시킨다.

### `src/debug.js`

F3 또는 URL의 `?debug`로 충돌 타일, 그리드, 건물 footprint, 문, 접근 타일과 NPC 로밍 범위를 표시한다.

### `src/simulation.js`

플레이어 이동, NPC 로밍, 충돌, 카메라 보간을 담당한다. Activity Module이 이 파일을 직접 크게 수정하지 않도록 한다.

이동 템포는 `src/config.js`의 `MOVEMENT_CONFIG`에서 조절한다. 현재 플레이어 한 타일 이동 시간은 185ms, NPC는 260ms다. 플레이어는 타일 경계에서 속도가 끊기지 않도록 일정 속도 보간을 사용한다. PC 키보드는 다음 한 칸 입력을 버퍼링하고, PC 포인터 환경에서만 캐릭터 위치를 서브픽셀 렌더링한다. 모바일의 기존 픽셀 스냅 경로는 유지한다.

### `src/rendering.js`

지형, 길, 물, 식생, 건물과 캐릭터를 그린다. 통과 가능한 식생은 actor 아래에 두고, 가림이 필요한 오브젝트는 공용 Y-depth 큐에 넣는다. 시간대 그라데이션·조명·밤 비네팅과 화면 전체 비·폭풍, 낚싯줄·찌도 이 렌더링 계층에서 처리한다.

### `src/interactions.js`

상황별 액션, 대화, 메뉴, 조이스틱, 터치 및 키보드 입력을 담당한다. 모바일 낚시 취소는 `pointerdown`이 아니라 `click`에서 처리해 고스트 클릭을 막는다. 도감·장비·도감 상세 팝업의 브라우저 뒤로가기 상태도 관리한다.

### `src/fishing.js`

낚시의 `idle → casting → waiting → bite → result` 상태 흐름과 지역·시간·날씨 필터, 상대 Weight 선택, 같은 어종 3연속 보정 및 XP·발견 통계 갱신을 담당한다. 장착한 낚싯대의 입질 대기 감소, 희귀 이상 Weight 증가와 큰 개체 보정도 최종 선택 단계에서 적용한다. 발견 수가 5/10/15/19/20에 도달하면 데이터에 선언된 보상을 한 번만 자동 지급한다. `?debug&fish=<fish.id>`는 실제 저장·결과 UI를 거치면서 지정 어종의 입질을 즉시 발생시키는 QA 전용 경로다. 어종과 보상 원본은 `src/data/fish-data.js`, 낚싯대 원본은 `src/data/fishing-gear-data.js`에 두며, 이 파일은 선택 규칙과 상태 전이에 집중한다.

### `src/data/life-skill-data.js` / `src/life-skills.js` / `src/skill-ui.js`

생활 스킬 6종의 공통 메타데이터와 요구 XP, Lv.100 이후 숙련도 계산, 진행도 카드·+XP·레벨업 UI를 담당한다. 현재 실제 획득과 저장까지 연결된 스킬은 낚시뿐이다. 기존 Lv.1–20 요구량은 유지하고 그 이후 요구량은 플레이 테스트 후 조정한다.

### `src/fishing-effects.js`

투척·입질·획득 시 `assets/fishing/audio/`의 사용자 제공 MP3를 각각 재생한다. 짧은 소리는 로딩 중 Web Audio 버퍼로 미리 디코딩해 즉시 시작하고, 오디오 컨텍스트는 첫 입력에서 활성화한다. 버퍼를 사용할 수 없는 환경에서는 HTML 오디오 재생으로 되돌아간다. 희귀·영웅·전설 결과의 파티클 수, 배너, 등장 애니메이션과 짧은 Web Audio 합성음도 담당한다. 일반·고급 결과에는 희귀도 전용 연출을 적용하지 않는다. 모션 감소 설정에서는 방사형 애니메이션을 숨기고 배너만 표시한다.

### `src/fish-dex.js`

저장된 `GAME_STATE.collections.fish`를 읽어 전체·연못·강·바다 필터, 발견 진행도, 다음 단계 보상, 발견 어종 통계와 미발견 출현 힌트를 렌더링한다. 15종 희귀어 힌트와 19종 마지막 단서 플래그에 따라 미발견 조건 공개 범위를 바꾼다. 발견한 어종은 `FISH_URLS`의 전용 픽셀 아트를 사용한다. 상세 정보는 중앙 팝업으로 열고 X·뒤로가기로 닫는다. 도감 열기·닫기 동안 공용 `menuOpen` 이동 잠금을 사용하며 발견 기록 자체는 변경하지 않는다.

### `src/data/fishing-gear-data.js` / `src/fishing-gear.js`

낚싯대 5종의 사용 조건과 입질·희귀도·크기 보너스를 데이터로 선언하고, 월드 메뉴의 전체 화면 장비 선택 UI를 렌더링한다. 잠긴 장비의 상세는 미리 볼 수 있지만 장착은 불가하다. 장착 시 즉시 저장한다. 장비 창도 도감과 같은 `menuOpen` 이동 잠금을 사용한다.

### `scripts/process-fish-assets.py`

`assets/fishing/source/`의 생성 원본에서 투명 영역을 자르고 알파 가장자리를 정리한 뒤, 최근접 보간으로 96×96 게임용 PNG와 검토용 contact sheet를 만든다. 런타임과 단일 HTML 빌드는 정규화된 20개 파일만 참조한다.

### `src/save.js`

저장 버전 v1과 `localStorage` 입출력을 담당한다. 인벤토리, 코인, 낚시 누적 XP·레벨·숙련도, 장착 낚싯대 ID, 어종별 발견 통계, 단계 보상 플래그와 강태공의 낚싯대를 형식 검증 후 복원한다. 과거 Lv.20 상한 저장의 누적 XP도 다시 계산해 Lv.21 이후 진행도로 복원한다. 저장 당시 장비가 현재 레벨·보상 기준으로 잠겨 있거나 ID가 유효하지 않으면 기본 낚싯대로 안전하게 되돌리며, 런타임 Activity 상태는 저장하지 않는다.

### `src/main.js`

에셋 준비 후 애니메이션 루프를 시작한다. 프레임마다 업데이트, 렌더링, 상황 문구 갱신을 순서대로 실행한다.

## 개발본과 배포본

- 개발본: 여러 소스와 이미지 파일을 사용하여 변경과 검토가 쉽다.
- 배포본: `node scripts/build.mjs`가 `dist/index.html` 하나로 합친다.

`dist/index.html`은 생성 파일이므로 직접 수정하거나 Git에 커밋하지 않는다.

### `src/world-time.js`

월드 전체가 공유하는 게임 시간과 시간대 판정, 시간대별 시각 보간값을 담당한다. 게임 1일은 현실 30분이며, 낚시·NPC·조명·날씨가 이 값을 읽고 각자 규칙을 적용한다.

### `src/weather.js`

6게임시간 단위 날씨 구간, 맑음·비·폭풍 확률, 하루 한 번 젖은 날씨를 보장하는 약한 보정과 개발자용 날씨 고정을 담당한다. 비·폭풍의 화면 효과는 렌더링 계층에서 그린다.

## 기능 추가 원칙

1. 기능 데이터와 규칙은 새 파일 또는 Activity Module에 둔다.
2. 이동·충돌·카메라 코어는 필요한 최소 범위만 변경한다.
3. 월드 상태를 변경하는 기능에는 저장 형식을 함께 정의한다.
4. 변경 후 `node scripts/check.mjs`와 `node scripts/build.mjs`로 구문, DOM 참조, 에셋, 배포 빌드를 확인한다.
5. 모바일 실기기에서 조이스틱과 화면 겹침을 최종 확인한다.
