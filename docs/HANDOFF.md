- 실제 Git 저장소는 작업 폴더 안의 `pixel-life-path-redesign-v5/`다. 최상위 폴더의 WAV·첨부·옛 `pixel-life-web/`는 현재 배포 저장소가 아니다.

## 3. 변경하지 말아야 할 사용자 결정

- 기본 도끼/기본 낚싯대는 내구도 무한이다. 벌목은 수종별 최소 도끼 제한 유지, 낮은 도끼의 상위 나무 도전/소프트 패널티는 추가하지 않는다.
- 기본 낚싯대·Lv.1도 장소/시간/날씨가 맞는 모든 74종에 도전할 수 있다. 상위 항로의 기존 해금과 승선권은 유지하며 어종에 새 강제 장비 제한을 넣지 않는다.
- 낚시는 성공 입질 후 획득 100%다. 미발견 `???` 물고기의 출현 힌트/조건은 끝까지 비공개, 잡은 물고기만 표시한다. 과거 15/19종 힌트 플래그는 호환용일 뿐 정답지를 다시 공개하지 않는다.
- 물고기 도감은 현재 `전체 / 내륙 / 해안 / 원양` 네 탭/3열 단일 목록이다. 하위 서식지 탭/접이식 구역은 없다. '바다' 명칭 제안은 별도 변경 승인이 확인되지 않았으므로 코드의 현재 이름을 유지한다.
- 완전 벌목의 목재는 0/1/2/3개 같은 확률(평균 1.5)이다. 0개여도 XP·도감·벤 횟수 지급, 무획득 전용 문구 없음. 완전 벌목 XP는 단계별 7/8/9/10/11/12/15/16/17/18이다. 공통 Lv.80 이후 요구량은 승인된 성장 v2를 사용하고 기존 레벨·바·숙련도는 한 번 환산해 보존한다.
- 유료 도끼는 실제 타격마다 나무 단계만큼 마모한다. 유료 낚싯대는 저장 성공 획득 때 내륙·해안 1/얕은 바다 6/중간 8/심해 10/빙하 12 마모, 취소는 무소모다.
- 내구도 0이 되는 마지막 타격/획득은 적용하고 빈손으로 저장한다. 마을 준/엘리에서 70% 손상 등 미리 부분 수리 가능, 구매 장비/파손 수리 장비는 가방에서 직접 장착한다. 사용 중 부분 수리 장비는 장착 유지한다.
- 귀환석(`Return Stone`, 내부 ID `village_return_charm`)은 준 도끼 탭에서 100코인 구매, 가방에서 1개 소모해 마을 북쪽 (25,3)으로 간다. 마을에서 잘못 사용해도 소모하며 저장 실패 때 수량/위치 원상 복원한다.
- 많이 반복하는 파밍은 허용한다. 콘텐츠/최종 장비보다 Lv.100이 먼저 되는 성장 역전은 모델로 검증한다. 임시 수치를 실제 Android 체감/모든 플레이의 보장이라고 표현하지 않는다.

## 4. 현재 숲 연결과 시각 표현

- 마을 남쪽 → 숲 1-1 → 남쪽 1-2 → 남쪽 1-3 → 남쪽 1-4 → 남쪽 1-5 → 남쪽 거목 숲. 1-2~1-5의 기존 1/2/3단계 혼합과 거목 숲의 기존 1/4단계 혼합은 유지한다.
- 일반 상위 숲은 1-1에서 붉은 거목림(북서쪽), 은빛 경목림(서쪽 아래), 검은 경목림(동쪽)으로 나눈다. 현재 각 한 맵이며 미래 확장 방향은 각각 북쪽/서쪽/동쪽이다.
- 마을 북쪽은 고대 → 정령 → 태초의 판타지 숲. 산악 호수는 1-1 서쪽 위, 폭포는 호수 남쪽, 늪은 폭포 남쪽. 기존 농장/항구 연결 유지.
- 기존 나무 2,565그루 ID/좌표/수종·물/바위·출구/도착·경제 기준선은 그대로다. 길옆 고정 나무 팻말 27개를 읽으며 기둥만 기존 방식의 한 타일 충돌을 가진다. 떠 있는 초록 안내/노란 육지 출구 표시는 다시 넣지 않는다.
- 마을/항구의 벽돌 격자 바닥은 흙·잔돌 표면으로 교체했다. 새 집은 다양한 크기·문/바닥/깊이 기준을 갖는다.

이전 시각 정비·QA 정리에 남은 필수 마무리는 없다. 농장 부지/통로/밭 상시 충돌/기본 낫의 사용자 결정은 적용했다. 다음 추천은 **농사 성장 설계**이며 XP/상위 낫 등 추가 구현 승인은 아직 없다.

2. **성장 설계:** 수확 XP/레벨/해금·경제/반복 목표·기존 밭/심은 작물/씨앗/진행 보존을 먼저 정한다. 이미 있는 밭 구매·오프라인 성장을 새 기능으로 반복 구현하지 않는다.

4. **도구:** 기본 무한 낫의 한 칸 수확은 구현됐다. 상위 낫의 범위/속도·내구도·업그레이드 재료는 밭 확장과 함께 별도로 정한다. 10개 장비부터 먼저 만들지 않고 작은 루프에서 검증한다.

## 7. 용량과 QA 보존 운영

2026-10-12 측정: 전체 작업 폴더 약 **1.13GiB**, 실제 Git 저장소 약 923MiB, 배포 dist 약 35.73MiB. 고해상도 제작 원본/테스트/Git 기록 때문에 작업 폴더가 크며 사용자에게 전체가 전달되는 것이 아니다. 상세는 [PROJECT_STORAGE.md](PROJECT_STORAGE.md)다.

- 사용자 승인으로 오래된 QA 2,618개 파일 약 416.03MiB를 휴지통에 옮겼다. `output/`은 약 605.64→189.62MiB다.
- 검사별 최신/직전 비교/중요 재현 자료와 실제 게임·원화·프롬프트·음악·첨부·검사 코드·기준선·Git 기록은 보존했다. 남긴 내용 SHA-256은 전후 동일하다.
- 휴지통에서 복원 가능하며 휴지통은 비우지 않았다. 실제 디스크 여유 공간은 비울 때 확보된다. 원화/WAV/Git 기록을 더 정리한 승인으로 확대하지 않는다.
- `output/` 전체는 Git 제외. 기본 결과 경로와 직전 비교 폴더 하나를 재사용하며 작업 종료 때 임시 결과를 검토한다. 새/정체불명 폴더·미해결 실패는 자동 삭제하지 않는다.
- [QA_RETENTION.md](QA_RETENTION.md)와 `scripts/qa-retention.ps1`을 따른다. 기본은 미리보기, `-Apply`는 검토한 지문 일치 대상만 휴지통으로 보낸다. 신규/변경 결과에는 오래된 목록을 억지 적용하지 않는다.
- 성공 기록 `output/qa-retention/recycle-2026-10-12.json`. 과거 문서의 정리된 `output/...` 경로는 과거 기록이며 파일 존재를 현재 상태로 주장하지 않는다.

## 8. 확인 명령과 작업 규칙

저장소에서 실행한다. 브라우저 검사에는 Playwright/Chrome과 로컬 서버가 필요하다. 현재 세션의 런타임 경로를 확인해 `PIXEL_LIFE_PLAYWRIGHT`, `PIXEL_LIFE_CHROME`, `PIXEL_LIFE_QA_URL`을 설정하고 사용자 브라우저 저장이 아닌 별도 검사 컨텍스트를 쓴다.

```text
git status --short
git fetch origin main
git rev-list --left-right --count HEAD...origin/main
node scripts/check.mjs
node scripts/build.mjs
git diff --check
```

맵/그림 수정 시 관련 `qa-forest-routes`, `qa-biome-scenery`, `qa-wood-bridges` 단위/브라우저 검사를 선택하고, 낚시/장비 변경은 해당 저장/거래/수리/운항 회귀를 실행한다. 캐릭터/검 보호 검사는 유지한다.

- dist는 생성물이며 직접 수정/커밋하지 않는다. 원화 source와 QA output은 다른 보존 대상이다.
- source/빌드는 GitHub Pages와 동일한 내용인지 확인하고 기능 변경 후 공개 화면까지 검증한다.
- 이미지 교체는 기존 게임 스타일·정확한 원본/프롬프트·기계적 패킹 기록을 유지한다. 사용자/다른 세션 변경을 덮지 않는다.
- 통과 가능한 식생은 actor 아래, 고정 물체는 공용 깊이 정렬. 모바일 이동 감각과 기존 충돌/저장 계약을 보존한다.
- 배포/PWA/독립 HTML의 외부 음악 파일과 현재 검사 방법은 [DEPLOYMENT.md](DEPLOYMENT.md), 모듈 책임은 [ARCHITECTURE.md](ARCHITECTURE.md)를 따른다.
