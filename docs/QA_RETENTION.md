# QA 결과 보존·정리 정책

기준일: 2026-10-12. 사용자 승인: 최신 결과 + 직전 비교 결과 + 중요한 버그 재현 자료만 남긴다.

## 무엇을 남기는가

- 검사 종류별 최신 성공 결과와 직전 비교용 결과를 남긴다. 마을/숲/낚시/도감/내구도/운항/캐릭터 등 서로 다른 검사를 하나의 최근 날짜로 묶어 삭제하지 않는다.
- 최신 로컬/공개 결과가 한 회차를 증명하는 경우 함께 보존할 수 있다. 모바일 크기·낮/밤/비·저장 실패 등 한 검사에 포함된 상황은 결과 폴더 전체를 보존한다.
- 목 연결·옆면·발 정렬, 숨김 힌트·운항 추월 방지·저장/파손과 같은 중요 문제는 해당 재현/수정 비교 자료를 명시적으로 고정한다.
- 최신 결과가 성공하기 전에는 직전 성공 결과를 버리지 않는다. 해결되지 않은 오류는 오래됐다는 이유만으로 삭제하지 않는다.
- 원화 제작본/프롬프트/게임 리소스/검사 코드/기준선 JSON은 테스트 캡처와 별개다. `assets/`, `src/`, `scripts/`, 게임 저장, `.git/`, 음원·첨부 파일은 이 정리 대상이 아니다.

## 앞으로 쌓이지 않게 하는 방식

1. 검사마다 기존 기본 출력 경로를 재사용한다. 기본 폴더를 최신 성공 결과, 별도 비교 폴더 하나를 직전 성공 결과로 관리한다.
2. 새 작업명/커밋/상황별 폴더는 임시 결과다. 작업 완료 시 최신과 직전 회차를 선정한 뒤 나머지를 검토·정리한다. 날짜만으로 전체를 자동 삭제하지 않는다.
3. 중요한 실패/재현 결과는 검사명·문제·보존 이유를 기록해 고정한다. 신규·정체불명 폴더는 임의 정리하지 않는다.
4. `output/` 전체는 Git에서 제외한다. 정책·보존 목록과 작은 정리 기록만 관리하며 화면 캡처를 저장소에 추가하지 않는다.
5. 과거 QA 문서의 `output/...` 경로는 그 회차의 기록이다. 오래된 임시 결과가 정리된 경우 검사 코드/보존된 최신 보고서로 다시 확인하고, 과거 화면을 현재 결과라고 제시하지 않는다.

## 이번 정리의 정확한 범위

`QA_RETENTION_V1.json`에 13개 검사 묶음의 최신/직전/고정 목록과 부분 보존 파일을 기록했다. 캐릭터 기본 검사/주민 이전 비교의 대표 화면은 남기고, 오래된 반복 실행 하위 폴더와 목 비교에 끼어 있던 단일 HTML 빌드 사본 3개는 정리한다. 첨부 원본은 건드리지 않는다.

검토된 정리 대상은 166개 파일/폴더 단위, 내부 파일 2,618개, 총 436,243,404바이트(약 416.03MiB)다. 시작 `output/` 635,058,688바이트(605.64MiB)에서 약 189.61MiB의 검사 자료를 남긴다. 작은 정리 보고서는 추가된다.

정리는 영구 삭제가 아니라 **Windows 휴지통 이동**이다. 휴지통에서 원래 위치로 복원할 수 있다. 휴지통을 비우기 전에는 프로젝트 폴더 크기는 줄어도 드라이브의 실제 여유 공간은 그만큼 늘지 않는다. 다른 휴지통 내용까지 임의 비우지 않는다.

## 정리 도구의 안전장치

`scripts/qa-retention.ps1`은 기본 실행이 삭제 없는 미리보기다. `-Apply`를 붙여야 검토된 목록만 휴지통으로 보낸다.

- 실행 위치와 무관하게 저장소 내부의 정확한 `output/`만 대상으로 한다. 루트 전체/부모/절대 경로·경로 탈출은 거부한다.
- 링크/재분석 지점이나 Git 추적 결과가 있으면 중단한다.
- 보호 목록을 포함하는 상위 폴더 정리는 거부한다.
- 검토 당시 파일 수·바이트·상대 경로/수정 시각 지문이 바뀌면 첫 정리 전에 중단한다. 적용 직전에도 재검사한다.
- 보존 파일의 실제 내용 SHA-256을 전후 비교한다. 성공 기록은 `output/qa-retention/recycle-2026-10-12.json`이다.
- 휴지통 실패 시 영구 삭제로 바꾸지 않는다. 이미 정리된 항목은 건너뛰며 재실행으로 기존 성공 기록을 덮지 않는다.
- `-Snapshot`은 새 검토 지문을 출력만 한다. 나중에 새 결과가 생겨도 자동 삭제하지 않는다. 보존/정리 목록을 새로 검토한 다음 새 지문을 명시적으로 반영해야 한다.
